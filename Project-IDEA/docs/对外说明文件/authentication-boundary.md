# IDEA 认证边界

## 当前状态

当前使用**预置账号密码登录**：不开放自助注册，不发送邮箱验证码。账号由 Project IDEA 管理员在服务端预置；服务端数据库仅保存使用 `scrypt` 加盐计算的密码哈希。

当前服务端已经具备：

- 账号与主体分离；
- Access Token 与 Refresh Token；
- Token 绑定设备会话；
- Owner 账号关联；
- Owner 设备 `pending`、`approved`、`revoked` 状态；
- Owner 新设备在批准前只能被路由到 `idea_assistant`，批准并重新登录后才能进入 `idea`；
- 设备撤销后的 Access Token 与 Refresh Token 即时失效；
- 普通预置账号失败登录限流；
- Owner 登录不受普通账号失败限流约束；
- 访客 `idea_assistant` 与 Owner `idea` 的服务端强制路由。

## 账号种子与凭据边界

- 预置账号明文种子仅保存在本机 Git 忽略的私有目录中，用于内部部署和账号交接；不得写入源码、文档、日志、截图或 Git。
- 服务器初始化完成后，只保留密码哈希；临时上传的账号种子必须删除。
- Owner 账号视为已完成注册，但仍不能绕过 Owner 设备审批。
- 普通预置账号是当前受控验收用的临时账号；待正式注册流程完成后应撤销或清除。
- 部署引导 Token 不能作为普通用户登录凭据。

## 冻结事项

以下能力当前没有开放：

- 自助账号注册；
- 邮箱验证码发送与验证；
- 密码找回、密码重置和邮箱变更；
- 面向公网用户的正式账号恢复与风控流程；
- 个体开发阶段直接接入短信验证码供应商。

## 正式认证前置条件

恢复自助注册或正式多用户认证前，需要先确定以下事项：

1. 设计账户注册、密码重置、邮箱变更和账号恢复流程。
2. 为登录、刷新、登出、设备注册和异常尝试建立限流、审计与风控策略。
3. 明确设备丢失、Owner 设备批准和紧急撤销流程。
4. 验证不同设备、不同网络和客户端重装后的会话行为。
5. 将当前预置账号机制与正式生产认证实现分离。

## 验收边界

跨设备验收可以证明服务端的账号关联、设备批准、记忆同步、revision 冲突和即时撤销正确；它不能证明当前已经完成正式用户注册、账号恢复或生产级风控。
