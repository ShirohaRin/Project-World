01 · 定位

平台定位：科研 · 生活 · 创作三位一体

三位一体的产品

在通用平台阶段，我们的产品是生物科研智能体、日常生活助理与个人创作助手三个角色的结合。它们共享同一套平台能力：记忆、知识库、受控工具调用与任务管理。用户不需要为每个场景安装不同系统，而是在统一工作面上按需启用角色。

科研角色

围绕科研工作流组织能力：文献检索与解读、资料整理、数据分析辅助、结论归纳与待验证假设提出，强调证据可追溯。

生活与创作角色

生活角色承担日程、提醒、资料整理与跨设备事务交接；创作角色辅助写作、构思与结构化表达。两类能力共用记忆与任务基础设施。

平台阶段后的分化

平台开发完成后，生物科研方向将转向实验室特化与虚拟细胞开发两条路径同时尝试；通用平台上的科研智能体不再新增特化功能，只做性能维护与优化，把研发资源让渡给两条新路径。

02 · 需求一

长期记忆自维护算法

背景

记忆如果只增不减，会越存越杂：重复信息堆积、冲突事实并存、过期内容稀释召回质量，最终拖慢每次回答并消耗上下文预算。当前记忆是分层记录加关键词召回，缺少主动整理能力。

要解决的问题

  • 重复与近义事实如何自动合并，不重复写入。
  • 矛盾事实如何识别、标注并保留证据，而非以新盖旧。
  • 过期与低价值记忆如何自然降权、归档或遗忘。
  • 自动整理如何不干扰前台对话、可回滚、可解释。

能力目标

让记忆像会自我整理的知识库：异步提炼会话要点、识别实体与事实、检测冲突与重复、维护重要度评分与时间衰减；整理结果进入候选区，经规则或轻量确认后生效。

验收方向

模拟多轮对话后，重复事实只保留一份、冲突被显式标注、旧结论可按时间回看；整理任务失败不阻塞前台，删除与修正可追溯。

03 · 需求二

文献处理能力

背景

科研依赖大量文献，但 PDF 是排版文档而非结构化数据。整篇灌入无法精确定位，逐字阅读又成本过高。科研智能体要给出可核验结论，必须先解决“文献如何被理解与引用”。

要解决的问题

  • PDF 中的标题、摘要、方法、数据、结论如何结构化拆解。
  • 参考文献、引用与被引关系如何抽取并建立关联。
  • 结论与实验证据、数据表如何绑定，回答时能回链到原文位置。

能力目标

建立文献知识库：解析入库、结构化字段抽取、混合检索（关键词与向量）、引用回链；支持多篇文献对照与证据链呈现，回答标注“文献事实 / 推断 / 待验证”。

验收方向

对一组真实论文完成解析后，同一结论能定位到对应段落与图表；回答中的引用能跳回原文；来源、版本与权限过滤生效。

04 · 需求三

插件兼容能力

背景

平台要同时服务科研、生活与创作，单靠内置功能无法覆盖长尾需求。开放插件生态能把“平台做得少而稳”与“能力扩展得快”结合起来，前提是扩展是受控的、可撤销的。

要解决的问题

  • 插件如何声明能力与权限边界，避免越权访问。
  • 不同插件间的数据格式与接口如何保持稳定兼容。
  • 插件升级、禁用、卸载如何干净执行而不影响核心。

能力目标

建立注册表式插件机制：插件集中登记、版本化 schema、受控接口调用；主程序提供稳定 API，插件通过声明式清单获取所需能力；权限由平台策略判断，插件不能自授权限。

验收方向

示例插件可在不修改核心代码的情况下注册、启用与禁用；越权调用被拒绝并记录；插件崩溃不影响主程序。

05 · 需求四

智能硬件扩展能力

背景

日常生活助理要触达真实世界，往往需要连接外部设备：输入设备、传感设备与桌面周边的智能硬件。硬件种类繁多、协议各异，需要一套统一的接入抽象。

要解决的问题

  • 不同硬件协议与数据格式如何统一为设备能力模型。
  • 硬件调用如何经过授权、审批与审计，避免越权控制。
  • 桌面客户端如何成为本地控制中枢而非依赖云端转发。

能力目标

定义标准化硬件接入协议与设备能力抽象：设备声明能力（读取、状态、指令）、平台做授权与审批、事件回收进记忆与上下文；新设备通过驱动插件接入，不改动核心。

验收方向

接入示例设备后能完成指令下发、状态回读与事件记录；无授权设备不可用；控制记录进入审计。

06 · 关系与优先级

四个需求的关系与优先级

相互支撑

文献处理依赖记忆承载知识来源，记忆自维护受益于文献的结构化元数据；插件提供硬件驱动与场景扩展，而硬件事件又成为记忆的新输入。四者共用平台底座。

阶段优先级

在通用平台阶段，优先级为：长期记忆自维护、文献处理能力先行（决定科研价值）；插件兼容能力为生态前提；智能硬件扩展在后段，依赖插件机制与权限体系成熟。

07 · 阶段路线

阶段路线与验收

通用平台阶段

三角色并行的平台打磨：记忆、文献、插件能力逐步稳定，日常与创作场景同步可用。

平台完成

科研角色停更新特化功能，转入实验室特化与虚拟细胞开发两条路径并行推进。

实验室特化

针对具体实验体系的深度适配：贴近湿实验流程、数据与验证环节。

虚拟细胞开发

构建可计算、可解释、可验证的细胞模型，共享平台记忆与数据治理基础。

08 · 边界

非目标与边界

边界声明

  • 科研角色不替代湿实验、临床判断与专业决策，只做辅助与证据组织。
  • 平台完成后通用科研智能体不再扩展特化功能，仅性能维护与优化。
  • 硬件接入以本地授权与审计为前提，不默认开放任意设备控制。
  • 插件不能自授权限，卸载与禁用必须干净可撤销。

成功定义

专业用户能更快完成科研、生活与创作任务，同时知道系统读了什么、依据什么、执行了什么，失败后能恢复，功能能按需扩展而不越界。
