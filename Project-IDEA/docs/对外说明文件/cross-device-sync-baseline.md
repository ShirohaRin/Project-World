# Project IDEA 跨设备同步基线

## 同步边界

Project World 的跨设备能力拆分为两条独立链路：

| 链路 | 唯一事实来源 | 当前用途 |
|---|---|---|
| 项目代码与脱敏文档 | GitHub 私有仓库 | Windows 与 Linux 上继续开发、审查与发布客户端代码 |
| 伊迪亚记忆、任务、会话与敏感项目上下文 | 受控 IDEA 服务端数据库 | 跨设备续接工作，不进入 GitHub、提交历史或发布包 |

Git 不承担聊天记忆、运行日志、数据库、令牌、模型配置、知识库原文或个人项目记忆的同步职责。文件级双向目录镜像也不作为代码同步方案；代码冲突由 Git 分支、提交和合并处理。

## 第一阶段目标

1. 将 Project World 建为 GitHub 私有仓库，Windows 与 Linux 使用相同远端仓库。
2. 将会话、消息、任务与事件持久化到 IDEA 服务端 SQLite，服务重启后仍可恢复。
3. 用事件游标让不同设备只拉取自身未见的任务和会话变化。
4. 桌面端先显示同步状态与可恢复任务；不自动同步或覆盖本地工作区文件。

## 代码协作流程

```text
Windows / Linux 工作区
  → git pull --rebase
  → 新分支或明确提交
  → 本地测试与构建
  → git push
  → 另一设备 git pull --rebase
```

发布桌面端时，源代码、构建配置和发布说明由 Git 同步；Windows 安装包或目录式输出作为 GitHub Release 附件发布，不提交到 Git 历史。

## 记忆与任务续接流程

```text
任意已连接设备
  → 创建或更新会话、任务、消息
  → 服务端写入 SQLite 业务记录与 sync_event
  → 返回 event_id / sequence
  → 另一设备按 cursor 拉取变化
  → 本地显示任务、会话摘要和待续接状态
```

事件协议只同步业务状态和脱敏摘要，不传输本地完整工作区文件。文件同步在后续阶段以内容哈希、版本基线、Diff、冲突状态和显式应用操作实现。

## 后续阶段

- 设备注册与能力上报。
- 工作区文件元数据、产物快照和冲突检测。
- 长期记忆的分域对象、来源、版本、显式写入确认与撤销。
- 受控设备动作、结果回传、离线队列与跨设备通知。

## 混合架构基线

跨设备 IDEA 不采用“所有请求和运算均在云端完成”的单体部署。平台职责分为控制平面与设备执行平面：

| 层级 | 节点 | 职责 |
|---|---|---|
| 控制平面 | 私有 IDEA 服务端 | 身份、Owner 路由、记忆、会话、任务、同步事件、审计和调度 |
| 主要执行平面 | 主力台式机 | 本地项目、构建、测试、未来 GPU 推理与重计算 |
| 协作执行节点 | 笔记本 | 移动开发、TRAE、轻量本地任务与客户端接入 |

云端负责保存持续的 IDEA 身份与协调跨设备任务。需要本地工作区、命令、GPU、屏幕或输入控制的任务，后续由已经登记、获 Owner 批准且具备相应能力的 Device Agent 执行；服务端保存任务、审计和结果，不直接假设可控制任意设备。

当前 TRAE 已可通过独立、可撤销的只读 MCP 凭据读取服务端长期记忆。下一阶段建设 Owner 专属 IDEA Agent 接入和 Device Agent，不能将现有只读记忆凭据扩展为隐式的 Agent 或设备执行凭据。
