## 项目背景

生物科技研发中的文献检索、阅读、证据核对和综述写作，往往分散在论文数据库、笔记工具、代码环境和多种通用 AI 工具中。研究人员需要反复整理研究问题、证据来源、实验方法和观点分歧，过程难以积累为可追溯的知识资产。

Program IDEA 拟建设本地优先的科研智能体工作平台。首期以文献调研与综述能力为切入点，在受控知识库和人工审核的前提下，支持检索、文献解析、证据组织、主题比较和综述草案生成；后续再扩展至模型训练、实验方法辅助与数据分析。

## 立项目标

1. 建立面向生物科技研发的文献知识底座，保留原始来源、元数据、访问权限和引用回链。
2. 交付可供研究人员试用的文献调研与综述 Agent，输出可审阅、可编辑、可追溯的研究材料。
3. 建立大模型训练与领域适配的评估框架，先验证任务价值和数据条件，再决定是否投入微调或训练。
4. 形成可复用的 Agent 开发、权限控制、结果审核与效果评估方法。

## 范围边界

| 类型   | 内容                                               |
| ---- | ------------------------------------------------ |
| 一期范围 | 文献接入与检索、论文结构化解析、主题调研、证据卡片、综述提纲与草案、引用核验、人工审核、任务记录 |
| 后续范围 | 实验方法预测、实验 SOP 辅助、科研数据分析、多 Agent 协作、模型微调或训练       |
| 暂不纳入 | 临床诊断与治疗建议、替代实验验证的结论、自动提交论文或自动发布科研结论              |
| 关键前提 | 获得导师立项支持；明确可使用的文献与内部资料范围；落实试点研究人员与基础算力资源         |

## 用户与场景

| 用户角色     | 核心任务          | 当前困难            | 一期价值            |
| -------- | ------------- | --------------- | --------------- |
| 研究生与科研助理 | 快速理解领域与撰写开题材料 | 阅读量大，笔记与引用分散    | 汇集证据、生成带引用的调研材料 |
| 课题负责人    | 评估研究方向与审阅综述   | 难以快速核对观点来源和证据强度 | 查看来源链路、分歧与待核验项  |
| 课题组成员    | 协作沉淀研究资料      | 结论难复用，资料交接成本高   | 形成项目级可检索知识资产    |

## 一期方案

| 模块       | 能力说明                       | 主要输出          | 验收标准          |
| -------- | -------------------------- | ------------- | ------------- |
| 文献知识库    | 接入公开论文与经授权资料，解析元数据、正文和引用关系 | 可检索的结构化文献库    | 每条文献保留来源与访问状态 |
| 调研 Agent | 围绕研究问题检索、归类、比较文献，并呈现证据依据   | 调研摘要、研究脉络、争议点 | 关键判断附可访问来源    |
| 综述 Agent | 将已确认材料组织为提纲、段落草案和引用清单      | 可编辑综述初稿       | 引用与文本主张可对应核验  |
| 审核与溯源    | 展示引用、版本、生成过程与人工修订          | 审阅记录、版本记录     | 用户可回看、修订或删除结果 |
| 评估体系     | 用真实课题建立任务集，衡量检索、引用和写作质量    | 评估报告          | 专家审阅与用户反馈形成结论 |

一期不建议直接训练基础大模型。现阶段应优先验证检索增强生成、提示策略、工具编排和领域评估的实际收益；在获得稳定的授权数据、明确的任务评估集与导师支持后，再评估参数高效微调或私有化模型部署。

## 技术与治理原则

- 平台保持本地优先，但离线桌面客户端必须依赖在线 Agent 运行时完成基础文档与工作区任务。
- 文献检索结果按权限过滤，回答需显示来源；无法确认的内容以待核验项呈现。
- 涉及内部资料、受监管数据或高风险研究内容时，遵循课题组既有审批与数据管理要求。
- 长期记忆仅保存经授权的项目知识和用户偏好，支持查看、修订、导出与删除。

## 成功指标

| 维度    | 一期判定方式                          |
| ----- | ------------------------------- |
| 可追溯性  | 试点任务中的关键结论均能定位到用户有权访问的文献来源      |
| 检索质量  | 由领域审阅者评价核心文献覆盖、主题相关性与遗漏情况       |
| 综述质量  | 由研究人员评价结构完整度、引用准确性、可编辑性和节省的整理时间 |
| 系统可靠性 | 完成规定样例任务，记录任务成功率、响应时间和失败原因      |
| 用户价值  | 试点用户愿意在实际课题中复用，并提出明确的后续使用场景     |

## 风险与决策事项

| 事项           | 影响             | 应对方向                          |
| ------------ | -------------- | ----------------------------- |
| 导师未支持立项或资源不足 | 项目无法获得稳定的试点与资源 | 先完成低成本概念验证，以演示样例争取支持          |
| 可用资料权限不清晰    | 可能造成资料使用风险     | 建立资料来源、授权和访问范围记录              |
| 生成内容缺少依据     | 影响科研可信度        | 强制引用回链，保留人工审核与不确定性提示          |
| 过早投入模型训练     | 成本高且难以评估收益     | 先通过 RAG 与 Agent 验证任务价值，再做训练决策 |
| 团队成员不足       | 开发周期延长         | 按知识底座和 Agent 原型优先级分阶段招募或协作    |

## 立项建议

建议采用“有条件立项”。首期以文献调研与综述 Agent 为明确交付边界，先获得导师对试点课题、数据使用范围和资源支持的确认。模型训练不作为一期硬性交付，而作为一期评估后单独决策的后续方向。
