# Project IDEA 图数据库数据模型设计

> 状态：设计文档（规划稿，尚未作为生产实现）
> 用途：为长期记忆自维护、文献知识库、Agent/插件/硬件关联提供图谱化的数据组织方案
> 阅读对象：后端与数据工程师、产品研发
> 关联文档：idea-memory-design.md、idea-project-architecture.md

## 1. 背景与目标

现有平台以 SQLite 等关系型存储承载会话、任务、记忆与授权，以向量检索支撑语义召回。关系模型擅长结构化事务，但当数据以"关系"为本体时——例如文献之间的引用、记忆之间的冲突与合并、角色与设备之间的授权链路——用关系表表达需要大量 join，难以回溯与推理。

图数据库以"节点 + 关系"为基本单元，适合表达：

- 记忆的推导链：Fact → Reflection → Evidence → Persona；
- 文献网络：论文 → 段落 → 图表 → 参考文献 → 被引论文；
- 权限链路：主体 → 设备 → 空间 → 资源；
- 扩展物联：Agent → 插件 → 设备 → 能力 → 事件。

本文定义建议采用的图数据模型，包括实体（节点）、关系（边）、属性、索引与查询模式。该模型与现有向量检索、关系型存储并行，不替代它们。

## 2. 存储选型建议

| 维度 | 建议 | 说明 |
|---|---|---|
| 图引擎 | 兼容 Cypher 的图数据库（如 Neo4j Community / Memgraph） | 生态成熟、查询语言可读性好 |
| 生产形态 | 容器化自托管，数据与日志持久化 | 与现有 Docker 部署一致 |
| 同步方案 | 以 SQLite / API 为权威源，图库作为投影 | 不把图库做成唯一事实源 |
| 备选 | 基于关系库自建边表 | 规模可控时可用，作为第一阶段降级方案 |

## 3. 全局模型总览

```text
(主体) --授权--> (空间/设备) --可访问--> (资源)

(文献) --包含--> (段落) --对应--> (图/表)
(段落) --引用--> (文献)
(文献) --受引于--> (文献)

(会话) --产生--> (记忆)
(记忆:Fact) --支撑--> (Reflection)
(Reflection) --强化/质疑--> (Evidence)

(Agent) --启用--> (插件) --驱动--> (设备)
(设备) --产生--> (事件) --沉淀--> (记忆)
```

## 4. 实体（节点）定义

### 4.1 主体与组织

| 节点 | 关键属性 | 说明 |
|---|---|---|
| Persona | persona_id, role, status | 用户/角色记忆容器 |
| OwnerAccount | account_id, email_hash, role | 平台 Owner |
| UserAccount | account_id, display_name | 普通成员 |
| Space | space_id, name, kind | 项目/空间边界 |
| Device | device_id, kind, state | 已登记设备 |
| Runtime | runtime_id, capabilities | 运行时注册 |

### 4.2 会话与任务

| 节点 | 关键属性 | 说明 |
|---|---|---|
| Session | session_id, created_at | 会话容器 |
| Message | message_id, role, created_at | 单条消息 |
| Task | task_id, state, revision | 任务执行单元 |
| Run | run_id, status, agent_ref | 一次执行 |
| Artifact | artifact_id, kind, uri | 产物/文件/补丁 |

### 4.3 记忆体系（与 idea-memory-design.md 对齐）

| 节点 | 关键属性 | 说明 |
|---|---|---|
| Journal | entry_id, ts | 原始消息索引 |
| Recent | memo_id, window | 近期摘要 |
| Fact | fact_id, text, confidence, status | 原子事实；status: candidate/confirmed/promoted/disputed/archived |
| Reflection | reflection_id, text, status | 跨事实合成判断 |
| Evidence | evidence_id, source_ref, polarity | 强化/质疑/确认证据 |
| Archive | entry_id | 已归档历史 |

### 4.4 文献与知识

| 节点 | 关键属性 | 说明 |
|---|---|---|
| Paper | paper_id, title, doi, year, source | 论文/文献 |
| Document | doc_id, path, format, revision | 通用文档 |
| Section | section_id, kind | 段落/章节 |
| Figure | figure_id, caption, locator | 图 |
| TableData | table_id, caption, locator | 表 |
| Concept | concept_id, name, type | 概念/术语/实体（如通路、蛋白、基因） |

### 4.5 扩展体系

| 节点 | 关键属性 | 说明 |
|---|---|---|
| Plugin | plugin_id, version, manifest_ref | 插件 |
| Skill | skill_id, version | 技能 |
| HardwareDevice | hw_id, protocol, capabilities | 智能硬件 |
| HardwareEvent | event_id, ts, payload_ref | 设备事件 |
| MCPEndpoint | endpoint_id, kind | 外部协议接入点 |

## 5. 关系（边）定义

### 5.1 授权与边界

| 关系 | 方向 | 说明 |
|---|---|---|
| OWNS | OwnerAccount → Device | 设备归属 |
| REGISTERED_ON | Runtime → Device | 运行注册 |
| BELONGS_TO | Persona/User → Space | 归属空间 |
| MEMBER_OF | UserAccount → Space | 空间成员 |
| CAN_ACCESS | Device/Runtime → Resource | 资源可访问 |
| GRANTS | Space → Resource | 授权授予 |

### 5.2 会话与任务

| 关系 | 方向 | 说明 |
|---|---|---|
| CONTAINS | Session → Message | 会话包含消息 |
| INITIATES | Session → Task | 会话发起任务 |
| EXECUTES | Task → Run | 任务产生运行 |
| PRODUCES | Run → Artifact | 运行产出产物 |
| DEPENDS_ON | Task → Task | 任务依赖 |
| REVISION_OF | Artifact → Artifact | 产物版本关系 |

### 5.3 记忆推导

| 关系 | 方向 | 说明 |
|---|---|---|
| DERIVED_FROM | Fact → Message | 事实来源消息 |
| SUPPORTS | Fact → Reflection | 事实支撑反思 |
| CONTRADICTS | Fact → Fact | 事实冲突（冲突并存） |
| MERGED_INTO | Fact → Fact | 去重合并 |
| SUPERSEDED_BY | Fact → Fact | 被替代 |
| EVIDENCED_BY | Fact/Reflection → Evidence | 证据强化 |
| OPPOSED_BY | Fact/Reflection → Evidence | 证据质疑 |
| ABOUT | Fact/Reflection → Concept | 涉及概念 |

### 5.4 文献网络

| 关系 | 方向 | 说明 |
|---|---|---|
| INCLUDES | Paper → Section | 论文含章节 |
| INCLUDES | Paper → Figure/TableData | 论文含图表 |
| CITES | Section → Paper | 引用他文 |
| CITED_BY | Paper → Paper | 被引（可由 CITES 推导/冗余） |
| MENTIONS | Section → Concept | 提及概念 |
| SUPPORTS | Section → Fact | 支撑某个事实/结论 |
| DERIVED_FROM | Fact → Section | 事实来源于段落 |
| RELATED_TO | Paper → Paper | 相似/相关 |

### 5.5 扩展与设备

| 关系 | 方向 | 说明 |
|---|---|---|
| ENABLES | Agent/Persona → Plugin | 启用插件 |
| DRIVES | Plugin → HardwareDevice | 驱动设备 |
| EMITS | HardwareDevice → HardwareEvent | 设备产生事件 |
| FEEDS_INTO | HardwareEvent → Memory/Fact | 事件沉淀为记忆 |
| REGISTERED_AT | MCPEndpoint → Space | 外部接入点归属 |

## 6. 属性设计要点

- 所有节点统一携带 `created_at`、`updated_at`、`source_system`、`revision`；
- 敏感内容只存引用（`ref`）或脱敏摘要，不把密钥、凭据与原文直接落到图库；
- 记忆与文献片段保留 `score`/`confidence` 便于排序；
- 冲突关系上记录 `detected_at` 与 `resolution`（pending/merged/kept）；
- 每个节点带 `space_id` 与 `visibility`，支撑权限过滤。

## 7. 索引与查询模式

### 7.1 关键索引

- Persona/Space/Device 的 id 唯一索引；
- Fact/Reflection 的 status 与时间索引；
- Paper 的 doi/title 索引；
- Concept 的 name 索引；
- 关系两端节点的起点/终点索引（自动）。

### 7.2 典型查询

- 记忆溯源：给定结论，沿 `SUPPORTS/DERIVED_FROM/EVIDENCED_BY` 回溯到原始消息与文献段落；
- 冲突检测：查 `CONTRADICTS` 关系，找出需人工裁决的事实对；
- 文献共引：给定概念，查关联论文及共同引用；
- 权限回溯：给定运行，沿设备→空间→资源判断是否越权；
- 记忆生命周期：按 status 与时间找可归档/可晋升的候选。

## 8. 权限与多租户隔离

- 图库存储层不做全局可见数据；查询统一附带 `space_id` 过滤；
- Owner/普通用户的节点与关系物理或逻辑分区，不跨空间无差别检索；
- 设备凭据、插件清单与硬件能力只允许授权主体读取；
- 删除采用逻辑删除标记 + 定时物理清理，保留审计轨迹。

## 9. 与现有存储的分工

| 存储 | 职责 |
|---|---|
| SQLite / API | 权威事实源：会话、任务、授权、审计 |
| 向量库 | 语义检索的候选召回 |
| 图数据库 | 关系推理、路径回溯、冲突与依赖分析（投影层） |

写入路径保持"主存储先落、图投影异步更新"，图库故障不影响前台主链路。

## 10. 边界与后续

- 本模型为规划稿，不承诺即期上线；
- 首期若数据规模可控，可用"边表 + 递归查询"在现有库上模拟核心关系查询；
- 图库成熟后逐步覆盖：记忆自维护的冲突裁决、文献引用网络、插件与设备的授权拓扑；
- 模型随记忆、文献与硬件需求的演进持续修订。
