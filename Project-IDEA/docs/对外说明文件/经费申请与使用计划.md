## 二、技术需求论证

### 2.1 任务定位

本项目所需算力并非用于从零预训练大模型，而是**在开源基座模型上进行领域参数微调**，使模型在生物领域的术语理解、知识问答与专业任务上获得针对性提升。这一区分对硬件选型具有决定性影响：微调不追求极致的峰值算力，而**高度依赖可用显存容量**。

### 2.2 显存需求测算

大模型微调的显存占用由四部分构成：模型权重、梯度、优化器状态、激活值。不同微调策略的显存差异极大：

| 模型规模    | 微调策略                    | 显存需求           | 本阶段定位      |
| ------- | ----------------------- | -------------- | ---------- |
| 70B     | 全参微调（AdamW）             | 约 560 GB 以上    | 本阶段不设为目标   |
| 70B     | LoRA（bf16 不量化）          | 约 140–160 GB   | 后续或追加预算后可选 |
| **70B** | **QLoRA（4-bit + LoRA）** | **约 46–48 GB** | **首期主力方案** |
| 32B     | QLoRA（4-bit + LoRA）     | 约 20–24 GB     | 备选方案       |
| 32B     | LoRA（bf16 不量化）          | 约 60–80 GB     | 备选进阶路径     |

数据来源：Runpod《Best GPU for Fine-Tuning》2026 年 9 月更新；Lyceum Technology《Which GPU for Fine-Tuning 70B Models》2026 年 8 月更新。测算条件为 batch size 1、中等序列长度、启用梯度检查点。

### 2.3 关键推论：为什么必须达到 80 GB 总显存

上表显示，70B 模型走 QLoRA 的显存下限约为 46–48 GB。**这构成了一条硬性门槛**：

1. **单卡 48 GB 属于踩线运行**。46–48 GB 是理论基线值，实际训练还需额外占用激活值、KV 缓存、数据加载缓冲区以及梯度检查点重计算时的峰值内存。序列长度增加或 batch 增大时，激活值占用将快速上升，随时可能触发显存溢出而中断训练。
2. **单卡 80 GB 是可靠下限**，可覆盖 70B QLoRA 并留出合理余量；双卡合计 80 GB 以上同样满足要求，且可通过分片进一步降低单卡压力。
3. **32B 备选方案对硬件要求显著更低**，24 GB 单卡即可完成 QLoRA，因此 80 GB 配置可同时覆盖首期与备选两个目标，不存在浪费。

### 2.4 为什么选择企业级计算卡而非消费级显卡

消费级显卡（GeForce 系列）在价格上具备吸引力，但用于本项目存在以下不可接受的限制：

| 限制项         | 具体影响                                      |
| ----------- | ----------------------------------------- |
| 无 ECC 显存    | 本项目训练任务需连续运行数天至数周，显存位翻转可能导致训练无声失败或模型质量下降  |
| 无 NVLink 互联 | 多卡通信被迫走 PCIe，扩展性与多卡并行效率受限                 |
| 驱动许可限制      | NVIDIA 终端用户许可协议禁止将 GeForce 驱动用于数据中心部署     |
| 显存容量上限低     | 消费级旗舰单卡 32 GB，双卡合计 64 GB，仍低于 70B 微调的可靠需求线 |
| 散热与供电设计     | 面向游戏负载设计，难以支撑 7×24 小时持续高负载运行              |

因此，本申请以企业级计算卡为选型方向。

## 五、分阶段实施计划

### 第一阶段：环境搭建与管线验证（设备验收后第 1–2 月）

- 部署 GPU 驱动、CUDA 与容器化训练环境；
- 搭建 PyTorch + DeepSpeed / FSDP + LLaMA-Factory（或 Axolotl）训练框架；
- 以 7B、13B 规模模型完成端到端冒烟测试，验证训练、断点续训、日志与评估链路；
- 完成 32B 规模的 QLoRA 微调全流程跑通，实测显存峰值与吞吐，为 70B 阶段提供参数依据；
- 建立领域数据清洗、去重、格式对齐与评测集构建流程。

**阶段产出**：可复现的训练管线、显存与吞吐基准报告、领域评测基线。

### 第二阶段：70B 模型领域微调（第 3–6 月）

- 实施 70B 模型 QLoRA 微调（4-bit 量化 + LoRA 秩 64），启用梯度检查点与分页优化器；
- 开展数据配比与课程学习实验，确定领域语料的有效混合比例；
- 建立多维度评测：领域知识问答准确率、专业术语一致性、指令遵循能力、通用能力保持度。

**阶段产出**：领域微调模型权重、评测报告、可复现的训练配置。

### 第三阶段：迭代优化与扩展评估（第 7–12 月）

- 开展超参数消融实验（LoRA 秩、学习率、序列长度、数据配比）；
- 评估是否需要突破 48 GB 显存门槛以支持 LoRA（bf16）或更长序列；如需扩展，按本节第四项提交追加预算申请；
- 沉淀训练规范文档，形成后续可复用的领域微调标准流程。

**扩容路径**：在现有平台基础上增配两张同型号计算卡，总显存提升至 160 GB，即可支持 LoRA（bf16）级别微调与更长序列训练。平台主板与电源按冗余设计选型，可承载 4 卡，无需更换主机。
