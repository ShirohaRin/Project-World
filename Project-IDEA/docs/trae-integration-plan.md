## 核心结论：需要 Linux 服务器

**是的，你需要 Linux 服务器。** 原因如下：

| 需求 | 本地无服务器 | Linux 服务器方案 |
|------|-------------|-----------------|
| 单机 TRAE IDE 使用 | ✅ Subagent 本地运行即可 | 更稳定 |
| **跨设备使用**（手机/网页/多台电脑） | ❌ 本地 subagent 绑定单机 | ✅ HTTP MCP 统一后端 |
| 持久化记忆/状态 | ❌ 会话结束即丢失 | ✅ 服务端持久存储 |
| 多智能体协调调度 | ❌ 靠 TRAE 内置调度 | ✅ 自定义协调逻辑 |
| 7×24 后台任务 | ❌ 依赖本地开机 | ✅ 服务始终在线 |

## 接入方式：双轨并行

### 轨一：TRAE Subagent（本地轻量版）

将每个 IDEA 智能体转化为 TRAE 的 **项目级 Subagent**（`.trae/agents/*.md`），在 TRAE IDE 本地直接使用。

**优点**：零额外部署，快速可用
**局限**：仅限单机，无跨设备能力，无持久化记忆

### 轨二：Linux MCP Server（服务端完整版）

在 Linux 服务器上部署 **HTTP MCP Server**，将所有 IDEA 智能体封装为 MCP 工具。TRAE 所有客户端（IDE / Work / 移动端）通过 HTTP MCP 连接。

**优点**：跨设备、持久化、7×24、复杂协调逻辑
**需要**：一台 Linux 服务器（你已有的），开放一个 HTTP 端口

## 历史推荐实施路径（待重新评审）

### 第一步：先部署 Subagent（立即可用）

在当前项目 `d:\Program-IDEA\` 下创建 `.trae/agents/` 目录，每个 IDEA 智能体一个 subagent 文件。通过 TRAE IDE 直接测试。

### 第二步：搭建 Linux MCP Server（延期）

在 Linux 服务器上部署 Python/Node.js MCP Server，暴露 HTTP 接口。这是跨设备的关键基础设施。

### 第三步：TRAE 连接 MCP Server（延期）

在 TRAE IDE / TRAE Work 中添加 HTTP 类型 MCP Server，指向你的 Linux 服务器地址。

### 第四步：飞书接入（后续阶段，延期）

在 MCP Server 上集成飞书 API，实现 TRAE ↔ IDEA ↔ 飞书 完整链路。

## Linux 服务器要求

| 项目 | 最低要求 | 推荐 |
|------|---------|------|
| CPU | 2 核 | 4 核 |
| 内存 | 4 GB | 8 GB |
| 磁盘 | 20 GB | 50 GB SSD |
| 系统 | Ubuntu 20.04+ / Debian 11+ / CentOS 8+ | Ubuntu 22.04 LTS |
| 网络 | 公网 IP（或内网穿透） | 域名 + HTTPS |
| 运行时 | Python 3.10+ 或 Node.js 18+ | Python 3.11+ |

---

## 安全注意事项

1. MCP Server 必须启用 **Token 鉴权**（HTTP Header `Authorization: Bearer xxx`）
2. 建议配置 **HTTPS**（Nginx 反向代理 + Let's Encrypt）
3. 限制 MCP Server 的文件访问范围（沙箱模式）
4. 所有智能体调用链记录**审计日志**
