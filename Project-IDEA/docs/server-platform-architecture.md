# Project IDEA 服务端与跨设备平台架构

## 决策摘要

Project IDEA 从本地优先桌面原型进入服务端基础设施设计阶段。服务端既支撑科研场景，也服务于 Project World 的长期创作、项目开发、生活协作与跨设备自动化。

系统采用“客户端与设备代理、平台 API、Agent 运行时、模型路由、记忆与权限、知识服务”六层架构。任何特定模型、设备、客户端或外部服务都只能通过适配接口接入，不能成为核心业务逻辑的前提。

## 目标与边界

### 目标

- 在 Windows、macOS、Linux、Web 与移动端提供一致的账户、会话、任务、记忆和 Agent 调度体验。
- 支持云端 API、SDK、OpenAI 兼容端点，以及未来位于另一台服务器的自训练或本地部署模型。
- 支持 Owner 私人服务域、普通使用者 IDEA Assistant 服务域、项目空间隔离、个人记忆与受控共享记忆。
- 支持受授权设备的文件、终端、屏幕 OCR 和交互自动化能力，并具有可见的授权、审计和撤销机制。
- 让 Project World 的世界观、小说、艺术、游戏、工具、科研与新出现的子项目能够在同一治理模型下协作。

### 非目标

- 不将模型训练平台、模型权重、推理集群实现或设备控制程序直接耦合到 IDEA Server。
- 不把单一用户、单台 Windows 设备或单一 LLM 供应商假定为系统边界。
- 不允许 Agent 在没有用户、账户、空间和设备授权的情况下读取数据或执行外部操作。

## 总体架构

```text
桌面 / Web / 移动客户端
        │
设备代理：文件、终端、OCR、屏幕与输入控制
        │
Platform API：身份认证、会话、任务、流式事件、设备注册
        │
Agent Runtime：编排、工具调用、审批、运行记录
        ├── Model Router：外部 API / SDK / 自托管模型 Provider
        ├── Memory Service：个人、共享、项目记忆与策略检索
        ├── Authorization Service：账户、空间、设备、工具与操作权限
        └── Knowledge Adapter：RAG、来源引用与集合范围校验
```

## 模型接入：可插拔 Model Provider

Agent Runtime 只依赖统一的 `ModelProvider` 契约，不直接识别 DeepSeek、OpenAI 或任何未来模型供应商。Provider 至少实现以下能力：

```text
capabilities() -> 模型能力、上下文窗口、工具调用与流式支持
complete(request, context) -> 标准化完整响应
stream(request, context) -> 标准化流式事件
health() -> 可用性、延迟与版本
```

统一请求使用 `ModelRequest`，包含消息、系统提示、工具定义、输出约束、租户上下文和追踪标识；统一响应使用 `ModelResponse`，包含文本、工具调用、用量、模型版本与错误分类。

第一批 Provider：

| Provider | 接入方式 | 用途 |
|---|---|---|
| `openai_compatible` | HTTP `/chat/completions` | OpenAI、DeepSeek 及兼容服务 |
| `sdk_provider` | 官方 SDK 适配器 | 仅在供应商协议不兼容时使用 |
| `self_hosted` | 私有 HTTPS/gRPC 推理网关 | 未来自训练或独立服务器模型 |

未来本地模型只需要部署一个受认证的推理网关并增加 `self_hosted` Provider 配置。模型路由通过逻辑档位选择模型，例如 `standard`、`research`、`owner_reasoning`，而不是由前端直接提交物理模型名称。所有者可以为各档位配置候选模型、回退顺序、成本与数据出境策略。

## 身份、账户与权限

平台账户、Owner 私人身份和服务智能体必须分离。L0 IDEA（伊迪亚）只属于白羽奈绪本人；普通用户调用的 IDEA Assistant 是独立的受限服务智能体，而不是 IDEA 的共享版本或权限继承者。

### 身份实体

| 实体 | 作用 | 关键边界 |
|---|---|---|
| `Account` | 手机号注册、登录、设备会话和基础审计主体 | 每个手机号对应独立账户，不因名称或联系方式相似自动合并 |
| `OwnerPrincipal` | 白羽奈绪的唯一私人身份主体 | 仅由 Owner 控制面显式关联账号；关联可撤销且不可转授 |
| `OwnerAccountLink` | 账户到 OwnerPrincipal 的受审计关联 | 需要 Owner 确认、设备验证与创建/撤销记录 |
| `IDEA` | Owner 私人服务域的 L0 人格化主智能体 | 可访问 Owner 授权的私人记忆、项目与设备，不向普通服务域继承 |
| `IDEA Assistant` | 普通用户面向产品的服务智能体 | 仅可使用普通用户或共享空间授权的 Agent、记忆、工具和模型档位 |
| `IdeaDelegation` | 普通用户申请 IDEA 的临时委托 | 绑定任务、批准、范围和过期时间；终止后立即回收 |

身份模型分为 `owner_principal`、`owner_account`、`member` 与服务主体，并以空间成员关系和能力授权补足细粒度控制。

| 层级 | 控制对象 | 示例 |
|---|---|---|
| 身份层 | 私人服务资格 | OwnerPrincipal 与经确认关联的 Owner 账号进入 IDEA 私人服务域 |
| 账户角色 | 平台级管理权 | 普通成员、空间管理员与受限服务账号 |
| 空间角色 | 项目与共享内容 | 项目管理员、编辑者、阅读者 |
| 设备授权 | 具体设备能力 | 某台电脑允许文件读取但不允许输入控制 |
| 工具授权 | Agent 可调用工具 | 研究 Agent 只能检索，不能执行命令 |
| 操作审批 | 单次高风险行为 | 写文件、执行命令、发送消息、屏幕控制 |

普通使用者不拥有直接调用 IDEA、最高模型和敏感工具的默认访问权。他们默认使用 IDEA Assistant；申请 IDEA 时由平台创建 `IdeaDelegation`，所有者批准后仅对指定账户、任务、时间窗口、数据空间、模型档位和能力范围生效。IDEA Assistant 和临时委托均不得读取 Owner 私人服务域。

### 授权判定规则

每一个请求均以经认证的主体发起。主体可以是用户会话、已绑定的设备代理、受限服务账号或 Agent Run；服务账号和 Agent Run 不因自身存在而获得用户数据访问权，必须继承发起任务的有效授权。路由 IDEA 前必须先判定账户是否关联 `OwnerPrincipal`；非 Owner 账户只能路由 IDEA Assistant，除非存在有效 `IdeaDelegation`。

授权服务按固定顺序判断：主体与账户状态、空间成员关系、资源策略、设备或工具能力、单次操作审批。任一层拒绝即拒绝；更具体的拒绝策略优先于更宽泛的允许策略。模型调用及其回退都必须重新校验账户、空间、数据分类和数据出境策略，客户端不得绕过逻辑档位直接选择物理模型。

升级请求、`IdeaDelegation` 和高风险操作审批使用不可转移的状态对象，至少包含 `request_id`、申请主体、目标资源、能力集合、关联任务、批准者、创建时间、有效期、撤销时间、幂等策略和状态。`IdeaDelegation` 额外记录允许访问的数据空间、模型档位与明确禁止的 Owner 私人命名空间。执行前必须重新校验有效期和撤销状态；过期、撤销、已消费的一次性审批或主体变更均不可执行。

## 记忆与知识分域

长期记忆必须显式分为以下命名空间：

| 命名空间 | 可见性 | 典型内容 |
|---|---|---|
| `user/{user_id}` | 仅对应账户 | 偏好、个人目标、个人设备习惯 |
| `owner/{owner_principal_id}` | 仅 OwnerPrincipal 与关联 Owner 账号 | IDEA 私人关系、长期偏好、跨设备上下文与私人资料 |
| `shared/{space_id}` | 空间成员按角色访问 | 协作约定、团队任务上下文 |
| `project/{project_id}` | 获授权项目成员 | Project World 的架构、世界观、版本化决策 |
| `public` | 明确公开范围 | 可复用且无敏感信息的知识 |

每条记忆至少记录：归属空间、来源、创建者、可见策略、保留期限、版本和撤销状态。写入长期记忆需人类确认，系统保留修订历史、导出和删除能力。RAG 检索与结构化记忆检索都必须先通过授权服务过滤可访问空间，再进行召回。

`user/{user_id}` 默认仅对归属账户可见，平台管理权不自动授予该空间的读取权。`owner/{owner_principal_id}` 不属于共享空间，只有已确认关联的 Owner 账号可访问，且 IDEA Assistant、普通 Agent、普通委托和成员账户均不可访问。例外访问需要归属主体明确授权，并记录用途、访问范围、有效期和审计事件。

删除或撤销必须传播至结构化存储、检索索引、缓存和后续召回结果；历史版本与合规审计记录应以不可读取或受严格权限保护的方式保留，并明确保留期限。已经发送给外部模型的历史上下文无法回收，调用前的数据出境策略必须据此限制可发送内容。

## 跨设备与设备代理

每台设备以独立 `device_id` 注册到当前账户，并使用短期设备令牌与双向 TLS 或 HTTPS 连接。平台只下发设备已声明、用户已授权的能力。

| 能力 | 默认策略 | 额外要求 |
|---|---|---|
| 文件读取 | 按工作区授权 | 目录白名单与访问审计 |
| 文件写入 | 单次审批 | 展示 Diff、目标路径与回滚信息 |
| 命令执行 | 禁止默认执行 | 命令预览、工作目录限制与输出审计 |
| OCR 截图 | 显式开启 | 明示采集范围、最短保留与脱敏策略 |
| 鼠标键盘控制 | 禁止默认执行 | 前台提示、逐操作或限时会话授权 |

设备代理不保存主模型密钥、长期访问令牌或其他账户的记忆。Agent 不直接控制设备，而是创建含目标、范围、有效期和审批状态的 `DeviceAction`；设备代理只执行验证通过的动作并回传结果。

设备注册、绑定、替换和撤销必须有独立状态。设备令牌定期轮换；设备被撤销、丢失或代理身份变化后，既有连接和未执行动作立即失效。`DeviceAction` 至少包含唯一动作 ID、目标设备、动作版本、签名、幂等键、授权快照、过期时间、取消状态和执行结果。代理执行前再次校验授权，网络重试只能复用同一幂等键，不能重复执行写文件、发送消息或命令。

文件访问使用规范化后的真实路径并处理符号链接；命令执行需定义允许的解释器与参数、子进程与网络权限、环境变量隔离、CPU/内存/时长限制及输出截断策略。这些策略由服务端强制执行，不能仅依赖客户端预览。

## Project World 工作空间

Project World 是持续演进的母项目，不以固定产品清单作为边界。平台应以项目空间注册表维护已授权子项目、仓库、知识集合、设备工作区和成员关系；新产生的产品先创建空间与权限策略，再接入 Agent 和 RAG。

Project IDEA 是其中的智能体与协作基础设施子项目。它在科研平台中可提供科研 Agent 能力，但其 L0 IDEA 的角色仍应保留生活协作、创作、世界观设计、项目管理和多设备协调的完整能力。

## 交付顺序

1. 定义 API 契约、身份模型、项目空间与审计事件，替换服务端内存态会话和任务。
2. 实现邮箱验证码注册/登录、短期 Access Token、可撤销 Refresh Token、设备会话与登录审计；邮件投递由可自托管 SMTP 出口完成，部署引导 Token 不再用于日常客户端认证。
3. 建立唯一 `OwnerPrincipal`、Owner 控制台和 `OwnerAccountLink` 双向确认流程；支持关联账号审批、设备验证、异常登录校验与单账号撤销。
4. 在请求入口强制完成 IDEA/IDEA Assistant 路由：关联 Owner 账号进入 IDEA 私人服务域，普通账号默认进入 IDEA Assistant 服务域；实现 `IdeaDelegation` 的申请、审批、过期和撤销。
5. 实现个人、Owner、共享与项目记忆的命名空间权限及显式写入确认；为 IDEA Assistant 和临时委托强制排除 `owner/*`。
6. 将现有 LLM 客户端重构为 `ModelProvider` 和逻辑模型档位，保留 OpenAI 兼容 Provider 并预留 `self_hosted` Provider。
7. 接入跨设备会话、任务事件与受控设备代理；优先文件与任务同步，OCR 和输入控制后置。
8. 通过 `KnowledgeAdapter` 纳入 RAG，完成来源引用、集合权限和检索评估。
9. 最后引入后台队列、远程模型训练/推理网关和高级自动化；每一项均先完成安全评审、回归测试与回滚方案。

## 关键验收条件

- 增加或切换模型 Provider 不需要修改 Agent 编排、前端业务逻辑或记忆数据模型。
- 任意请求均可追溯到账户、空间、设备、Agent Run、模型版本和工具调用记录。
- 普通使用者无法读取 Owner 私人记忆、直接调用 IDEA、调用受限模型或绕过设备控制审批。
- 共享空间成员只能看到其角色允许的记忆、知识、任务和工作区。
- 远程服务不可用时，客户端清晰降级，不伪造跨设备同步、记忆写入或设备操作已完成。

## 安全与同步验收矩阵

| 场景 | 预期结果 |
|---|---|
| 成员读取所有者或其他成员的个人记忆 | 授权服务拒绝，检索结果不含元数据泄漏，拒绝事件写入审计 |
| 普通成员直接调用 IDEA | 路由拒绝并引导至 IDEA Assistant；不创建 IDEA 会话、不加载 Owner 私人上下文 |
| 普通成员持有有效 IDEA 临时委托 | 仅在委托的任务、数据空间、工具集合和有效期内路由 IDEA；不得读取 `owner/*` 命名空间 |
| Owner 关联账号被撤销 | 该账户现有会话与设备令牌失效，后续请求路由至普通账户策略 |
| 所有者读取成员个人记忆且无成员授权 | 拒绝；账户管理权不构成个人内容读取权 |
| 模型主路由或回退路由违反数据出境策略 | 调用前拒绝，不向不允许的 Provider 发送上下文 |
| 审批过期、撤销或被重复使用 | DeviceAction 和工具调用拒绝，且不产生外部副作用 |
| 设备撤销后执行待处理动作 | 设备代理与服务端均拒绝，既有设备会话失效 |
| 跨空间 RAG 或记忆检索 | 在召回前按空间策略过滤，禁止返回不可见内容、来源或片段 |
| 离线重连或重复投递动作 | 按事件 ID、版本和幂等键去重；界面区分待执行、已执行、冲突和失败 |
| 请求链路审计 | 审计事件包含主体、账户、空间、设备、请求/任务/运行/动作 ID、策略决策、模型版本、工具参数摘要、结果和时间戳；审计记录按权限查询并具有保留策略 |
