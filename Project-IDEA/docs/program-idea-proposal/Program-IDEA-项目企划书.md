# Program IDEA 项目企划书

## 项目概述

**Program IDEA** 是面向知识工作与生物科技研发场景的集成式 Agents 工作平台。项目由“工作平台”和“科研 Agents”两部分组成：前者统一承载文档、演示文稿、代码、设计、对话、构建与自动化等日常生产活动；后者面向生物科技工作者提供基于可信知识的分析、推理与协作能力。

项目的目标是把分散的创作工具、开发工具、自动化能力和科研智能体收敛到同一工作入口，使用户能够在同一任务上下文中完成资料沉淀、内容生成、实验设计辅助、数据分析与交付物制作。平台将优先兼容并继承 TRAE、CodeBuddy、Codex 等生态中的插件与扩展能力，在统一权限、任务编排和记忆系统下提供一致体验。

## 建设背景

通用 AI 工具已经能够辅助撰写、编程和检索，但生物科技研发的实际工作仍面临三个断点：

- 研发资料分散于论文、实验记录、数据文件与内部知识库，难以形成可追溯的统一上下文。
- 通用模型对实验条件、方法边界与证据等级的理解不足，输出难以直接进入科研决策流程。
- 文档、代码、数据分析、实验总结等工作通常跨越多个应用，任务上下文和经验无法持续积累。

Program IDEA 以工作平台提供通用生产力底座，以科研 Agents 形成领域能力层。在可靠检索、权限治理和人工确认机制的约束下，逐步构建可复用的研发知识与方法资产。

## 项目愿景

形成一个可扩展、可治理、可追溯的智能工作环境：

1. 让用户以任务为中心使用文档、PPT、代码、设计、构建和自动化能力。
2. 让生物科技研发人员能够基于受控知识库完成论文理解、方法归纳、综述草拟与数据分析。
3. 让任务历史、用户偏好、已验证的方法和反馈在权限范围内沉淀为长期记忆。
4. 在满足数据安全、审计与成本边界的前提下，为后续本地模型部署和领域模型学习预留架构空间。

## 产品范围

### 工作平台

工作平台是 Program IDEA 的统一操作界面与任务调度层，提供以下能力：

| 模块 | 核心功能 | 目标价值 |
| --- | --- | --- |
| 文档 | 撰写、改写、结构化整理、版本协作 | 将资料和结论沉淀为可复用文档 |
| PPT | 演示结构规划、内容生成、视觉编排 | 缩短项目汇报与学术展示准备时间 |
| Code | 代码编写、解释、调试、测试与仓库协作 | 覆盖研发脚本、数据处理与服务开发 |
| Design | 界面草图、交互说明、设计资产协作 | 支持工具界面与科研可视化设计 |
| Chat | 多轮对话、任务拆解、上下文协作 | 提供统一的智能交互入口 |
| Build | 项目构建、运行、部署与环境管理 | 连接开发产物与实际服务运行 |
| 自动化 | 定时任务、工作流编排、通知与归档 | 将重复性工作转为可管理流程 |
| 插件生态 | 兼容 TRAE、CodeBuddy、Codex 等插件范式 | 降低用户和开发者的迁移成本 |

平台的关键原则是保持工具间的上下文连续性。例如，用户在论文分析任务中形成的方法结论，可直接被用于生成实验汇报、数据处理代码或后续自动化任务；每次跨模块调用均应保留来源、权限与执行记录。

### 生物科技 Agents

Agents 层面向生物科技工作者，围绕“知识检索、记忆积累、专业技能、任务协作”构建。首期能力以辅助分析和内容生成作为定位，不替代实验验证、临床判断或合规审批。

| 能力域 | 主要能力 | 输出形式 |
| --- | --- | --- |
| 生物科技 RAG 知识库 | 检索论文、方法文档、内部资料并提供证据来源 | 带引用的问答、证据摘要、知识卡片 |
| Long-term Memory | 保存经授权的偏好、任务上下文、验证结论与反馈 | 个性化提示、历史关联、经验复用 |
| 特化 Skill | 将论文、实验、数据等场景封装为可调用技能 | 参数化任务、标准化报告、可复用模板 |
| 强化学习论文分析 | 拆解问题定义、奖励设计、训练过程、评估与局限 | 论文结构化解读、对比表、研究路线 |
| 实验方法总结 | 归纳步骤、材料、条件、变量、风险与证据等级 | 方法摘要、SOP 草案、差异对照 |
| 实验方法预测 | 基于历史方法与约束提出候选方案及验证假设 | 候选路线、条件建议、风险提示 |
| 综述生成 | 聚合主题文献并按证据强度组织观点 | 综述提纲、章节草稿、引文清单 |
| 数据分析 | 辅助数据清洗、统计方案、可视化与代码生成 | 分析记录、图表说明、可复现脚本 |

### 能力边界

Program IDEA 的科研 Agents 应明确标注信息来源、适用范围与不确定性。实验方法预测、结果解释和统计建议必须保留人工审核入口；涉及人类受试者、临床决策、病原体、生物安全或受监管数据的任务，必须纳入组织既有的合规与审批流程。长期记忆仅记录经授权的信息，并支持查看、修订、导出与删除。

## 总体架构

平台采用四层结构：

1. **交互与工作层**：提供文档、PPT、Code、Design、Chat、Build、自动化等统一工作台，并承载插件交互。
2. **编排与插件层**：负责任务分解、Agent 调度、工具调用、插件适配、执行记录与错误恢复。
3. **知识与记忆层**：包括生物科技 RAG 服务、向量检索、文档解析、引用管理、Long-term Memory 和权限过滤。
4. **基础设施与治理层**：包括身份认证、角色权限、审计日志、密钥管理、存储、模型网关、监控与备份。

在该架构中，RAG 服务和权限系统是所有科研能力的先决条件。任何知识检索和记忆调用均应在权限过滤后执行，最终回答需要能回溯到可访问的原始资料或经确认的内部知识条目。

## 关键工作流

### 论文到研究计划

用户导入或检索论文后，论文分析 Skill 生成研究问题、方法、结果、局限与可复现性摘要；RAG 知识库补充相关工作并标记证据来源；用户确认后，平台将结构化结论同步到研究计划、汇报 PPT 或实验任务中。

### 实验方法辅助

用户输入目标、样本条件、可用设备和约束，Agent 从已授权的文献与内部方法中检索候选方案，输出步骤摘要、变量清单、预期风险和验证建议。该输出作为实验设计辅助材料，由研究人员进行判断和确认后才可形成正式 SOP。

### 数据分析交付

用户上传或连接数据后，平台记录数据版本与访问权限，Agent 建议清洗、统计和可视化路径，并生成可审阅代码。运行结果、图表与分析说明可直接整理为报告或演示文稿；所有关键结论应保留数据版本和代码版本关联。

## 实施阶段

项目分为六个阶段推进。阶段验收以可用能力、治理要求和用户反馈为共同依据，而不是仅以功能数量衡量。

| 阶段 | 核心工作 | 主要交付物 | 阶段出口 |
| --- | --- | --- | --- |
| 立项 | 明确目标用户、使用场景、范围、预算、治理责任和成功指标 | 项目章程、需求范围、风险登记、路线图 | 立项评审通过，负责人和资源到位 |
| 前置工作 | 搭建 RAG 服务平台与服务器权限系统，完成数据接入规则和基础监控 | 检索服务、文档解析链路、身份认证、角色权限、审计方案 | 受控资料可检索，访问权限可验证 |
| 平台开发 | 建设统一工作台、任务编排、插件适配与文档/PPT/Code 等基础能力 | 工作台 MVP、插件接口、任务记录、基础自动化 | 核心跨模块任务可端到端完成 |
| Agents 开发 | 建设生物科技 RAG、长期记忆、特化 Skill 与科研任务 Agent | 论文分析、方法总结、综述、数据分析等能力原型 | 输出可追溯，人工审核流程可用 |
| 用户测试 | 邀请目标研发人员在真实但受控的任务中试用，收集质量和体验数据 | 测试报告、问题分级、满意度与效率数据 | 高优先级风险已识别并形成修复计划 |
| 反馈修理 | 修复关键问题，优化提示、检索、权限、交互与稳定性 | 版本发布说明、回归报告、运营机制 | 达到上线门槛，形成持续迭代节奏 |

## 前置工作说明

### RAG 服务平台搭建

前置阶段应建设可独立演进的 RAG 服务平台，至少包括：资料接入与格式解析、分块与元数据处理、嵌入与索引、混合检索、重排序、引用回链、知识库版本管理和评估集。知识条目必须携带来源、发布时间、权限范围、领域标签和有效状态，避免将无出处或过期资料作为可靠结论。

首期建议优先接入公开论文、公开方法文档与已明确授权的内部资料；建立资料质量分级和失效机制。评估指标应覆盖检索命中率、引用准确性、答案可追溯率、延迟与权限拦截准确率。

### 服务器权限系统搭建

权限系统需覆盖用户身份、组织角色、项目空间、知识库、文件、记忆条目、插件和执行环境。建议采用最小权限原则，并对高风险操作增加审批、二次确认或隔离运行机制。

核心要求包括单点登录或统一身份接入、角色权限控制、项目级数据隔离、密钥托管、审计日志、操作留痕、异常访问告警和备份恢复。模型调用、插件调用与自动化任务均应使用可追踪的服务身份，不直接暴露长期凭据。

## 里程碑与指标

项目初期以质量、可追溯性与可控性为优先，效率指标在用户测试后再根据基线确定。建议采用以下衡量框架：

| 维度 | 建议衡量方式 |
| --- | --- |
| 平台可用性 | 核心任务成功率、关键页面响应时间、构建与自动化成功率 |
| 知识可靠性 | 引用覆盖率、引用正确率、检索命中率、过期资料拦截率 |
| 科研任务质量 | 专家评分、方法总结完整度、数据分析可复现率、错误率 |
| 安全与治理 | 权限拦截准确率、审计覆盖率、敏感数据违规访问次数 |
| 用户价值 | 任务完成时长变化、周活跃用户、复用率、满意度与反馈闭环率 |

## 主要风险与应对

| 风险 | 影响 | 应对方向 |
| --- | --- | --- |
| 知识来源质量不稳定 | 错误或过时结论影响研发判断 | 建立来源分级、版本管理、引用展示与人工审核 |
| 幻觉与不确定性表达不足 | 用户过度信任生成结果 | 要求证据回链、置信提示、关键结论人工确认 |
| 数据与权限泄露 | 影响合规、知识产权与用户信任 | 最小权限、项目隔离、审计、加密与密钥托管 |
| 插件兼容性复杂 | 平台稳定性与维护成本上升 | 制定插件适配层、权限沙箱、版本兼容策略 |
| 长期记忆失控 | 产生错误偏好或隐私风险 | 授权写入、可见可改可删、记忆质量评估 |
| 本地模型投入不确定 | 计算资源与维护成本增加 | 先保留模型网关与评估接口，以明确场景验证后再决策 |

## 后续演进

在核心平台和 Agents 经过用户验证后，可评估本地部署模型与领域学习能力。该阶段应以可量化的任务收益、数据可用性、算力成本、模型安全与运维能力为前提，避免为部署而部署。

可能的演进方向包括：针对内部知识和方法资产的私有化推理，面向特定科研任务的模型评测与微调，基于用户反馈的 Agent 策略优化，以及在安全隔离环境中开展模型学习实验。无论采用何种路径，模型训练数据、评测集和发布过程都需具备来源记录、权限依据与版本追踪。

## 结论

Program IDEA 将通用工作平台与生物科技特化 Agents 结合，既服务于文档、代码、设计和自动化等高频生产活动，也面向科研知识检索、论文分析、实验方法与数据分析等专业任务提供受控智能辅助。项目的首要建设重点是 RAG 服务平台和服务器权限系统；在此基础上，通过六阶段推进将能力从可用原型逐步推进到经用户验证、可持续迭代的产品体系。
