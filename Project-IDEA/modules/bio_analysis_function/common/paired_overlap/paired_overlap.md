# 双端 overlap 分析（paired_overlap）

> 本文件由《生物方法模块算法清单》5.4.6 节拆出；子节编号沿用原文档，便于与历史记录对照。


> 与 $5.4.4$ 同理：编号按开发顺序排在这里，但它按 `开发规则.md` 3.2 的**第 2 类**
> 归入**公共层**——产出（错位量/重叠长度/错配数）自身对用户没有意义，必须被进一步
> 处理。因此**没有独立入口**，由后续的双端算法调用。

### 5.4.6.1 选择依据

1. **它是双端数据一切处理的起点**。单端数据靠"找接头"（$5.4.4$/$5.4.5$）；双端数据
   有更好的信息：两条 read 来自同一片段，把 r2 反向互补后应当与 r1 在某处对齐——
   这个错位量一旦算出来，**接头在哪、该切多长、能不能合并、哪些碱基该校正**全都跟着
   出来了。因此它是双端侧三个功能（按 overlap 裁接头 / 重叠区碱基校正 / 双端合并）
   共同的前置。
2. **它有上游可逐行对照的源码与自带向量**（`OverlapAnalysis::test()`），可以逐位对齐。

### 5.4.6.3 问题定义与算法原理

把 r2 取**反向互补**（rc2）后，"两条 read 来自同一片段"就变成"r1 与 rc2 在某个错位量
上对齐"。做法是沿两个方向扫错位量，每个错位量都做一次判定：

- **正向**（`offset > 0`）：rc2 的起点落在 r1 内部（r1 的尾巴对 rc2 的头）。对应
  "片段**长于**读长、两条 read 只在中间重叠"，**没有接头**。
- **反向**（`offset < 0`）：rc2 的起点落在 r1 起点之前（r1 的头对 rc2 的中间）。对应
  "片段**短于**读长、两条 read 都读穿了片段"，此时 `overlap_len` 就是**片段长度**。
  注意接头出现在 **rc2 的开头**——反向互补会把 r2 尾部的接头翻到最前面，这一点很容易
  记反（本文档早期版本就写成了"接头在 rc2 尾部"）。
- 每个错位量要求重叠区**前 50 个碱基**内的错配不超过
  $\min(\text{diff\_limit},\ \lfloor \text{overlap\_len} \times \text{diff\_percent\_limit}\rfloor)$，
  而报出去的 `diff` 在重叠长度超过 50 时是**整段**的真实错配数。
  这个"判定只看前 50、报告给全部"的不对称是刻意的：它让"先匹配上、后面才开始错"的
  情形也能被认出来（上游第二组向量就是这件事：前 50 个完全相同、后 30 个全错，
  仍然判定为重叠，diff 报 30）。
- 扫不到再（可选）允许 1 个插入/缺失扫一遍（`allow_gap`），并把 `has_gap` 置真。
- 重叠长度不足 `require`（默认 30）一律判"不重叠"。

**片段长度**按上游 `PairEndProcessor::statInsertSize` 的两个分支取：`offset > 0` 时是
`len1 + len2 - overlap_len`（两条 read 各覆盖片段一头、中间重叠），`offset <= 0` 时就是
`overlap_len`（两端读穿，重叠长度本身就是片段）。这两条式子是上面符号约定的权威依据，
`OverlapResult.insert_size` 用的就是它们——**早期的 `overlap_len + offset` 是错的**，
在 `offset > 0` 时会明显偏小（片段 100、读长 80 时报成 80 而非 100）。

**上游三处实现特性**（都写进了测试）：

1. **缺口路径只认贴近末端的 indel**：`Matcher::diffWithOneInsertion` 的判定循环在
   "前缀累计错配"第一次超限时直接返回 −1，**即使它已经找到过更小的差值**。因此插入
   位置离被比较区域末尾越远越早被判否。
2. **扫描上界排除末尾**：正向那段是 `offset < len1 - require`，所以"只重叠到末尾
   `require` 个碱基"的位置不会被试到。
3. **`allow_gap`** **只在很窄的窗口里翻得动结论**（这条是实测 + 推演一起得到的）：
   要三条同时成立——重叠区不长（无缺口那一轮只判定前 50 个碱基，重叠区一大它先认下）、
   indel 贴着比对区末端、且无缺口那一轮恰好过不去。实测扫了 12000 组（含单碱基插入 /
   缺失 / 随机错配、读长 10\~151、多组参数），有 443 组由缺口那一轮给出结论；而
   读长 30\~151、重叠动辄上百的常规形态里，打开开关**一次都没改变结论**。
   逐位复现用的向量是 `common/paired_overlap/algorithm.py` 里的 `GAP_ONLY_VECTOR`
   （重叠 48 个碱基 + 末端 indel，公共层与原生层的测试共用这一份）。

### 5.4.6.5 适用边界与待办

- **已移植到原生层**（`bio::analyze_overlap` + C ABI `bio_analyze_overlap`）。
  它的成本是"错位量个数 × 每次最多 50 个碱基的比对"，比逐 read 的裁剪轻，
  但满量双端数据仍必须走原生层；Python 版从此只作逐位基准与规格。
- **缺口路径的实际价值有限**（见 $5.4.6.3$ 第 3 点）：只在"短重叠 + 末端 indel"的
  窄窗口里翻得动结论，上游 PE 主流程默认也不开它。保留是为了与上游行为一致。
- 待办：把 $5.4.6$ 之上的双端功能做成**用户可见的算法**——
  ③ **双端合并**已于 $5.4.7$ 完成（产出合并后的 FASTQ，是这批里最像"独立算法"的一个）；
  剩下两项未开始：① 双端模式下按 overlap 裁接头；② 重叠区低质量碱基校正。
  三者都要在原生层的流水线里消费 `bio::analyze_overlap`（成对的 read 由流水线提供，
  不跨语言逐对调用）——$5.4.7$ 已经按这条原则实现，可作后两项的模板。
