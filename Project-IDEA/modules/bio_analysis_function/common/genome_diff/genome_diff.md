# genome_diff：Genome Diff（`.gd`）读写

`.gd` 是 breseq 的机器可读产物格式，也是这条"参考比对与变异检测线"的**产物契约**：
产物不只应该有能看的 HTML，还应该有能机读、能互相比较、能与上游逐条对拍的文件。

```text
#=GENOME_DIFF	1.0
#=PROGRAM	breseq 0.33.1 revision 8505477f25b3
#=REFSEQ	/var/data/NC_000913_3.gb
#=MAPPED-BASES	434491437
DEL	2	35	NC_000913	701810	1	frequency=1.16257668e-01
SNP	5	37	NC_000913	1269450	T	frequency=1.04031563e-01
RA	37	.	NC_000913	1269450	0	C	T	consensus_score=133.2	prediction=polymorphism	...
```

上面这几行抄自一份公开的真实产物（**breseq 0.33.1**，ALE 数据库 aledb.org 里 pgi 进化实验的
`.../breseq/15-3-0-1/output/output.gd`），并对照同目录的 `index.html` 核对了每一列的含义
——本模块的格式规则都是从这份真实产物反推的，不是照文档猜的。

> **当前状态：A、B、C1、C2 四片全部完成。** 格式模型与解析、逐字节往返；从我们的结果构造记录
> 并装配；比较多份 `.gd`；给参考应用突变。共 **70 项测试**。
> 它是**工具不是算法**（`开发规则.md` 3.2 第 1 类），不做算法广场入口。

## 1. 现在能做什么

| 项 | 内容 |
| --- | --- |
| 输入 | `.gd` 文本（字符串或文件路径），按 UTF-8 读、兼容 CRLF |
| 输出①头 | `GenomeDiffHeader`：版本 + 若干 `#=键 值...` 元信息（保序，同名键可重复，因为双端测序会写两个 `#=READSEQ`） |
| 输出②记录 | `GenomeDiffRecord`：类型、编号、**证据编号列表**、参考名、位置（1-based）、类型特有字段、`key=value` 属性（保序） |
| 输出③整体 | `GenomeDiff`：`mutations()` / `evidence()` / `by_id()` / `evidence_of(突变)` |
| 输出④构造 | `substitution_record` / `deletion_record` / `insertion_record` / `read_alignment_evidence`：按上游同形的写法造记录（只吃基本值，不认识算法层的数据类） |
| 输出⑤装配 | `MutationEntry` + `assemble_diff`：自动编号（突变 `1..N`、证据接着 `N+1..M`）、回填证据列、按上游顺序输出 |
| 输出⑥比较 | `ComparisonTable`：多份样本对齐成"一行一条突变、一列一个样本"，`shared()` / `unique_to()` / `rows_of()` / `to_csv()` |
| 输出⑦应用 | `apply_mutations` / `apply_diff` → `AppliedGenome`：把突变贴回参考，得到新序列，并给出每条突变**在新序列里的位置** |
| 另可用 | `format_genome_diff`（写回文本）、`write_genome_diff`（写文件，返回记录数）、`compare_files`（按文件比较）、`EVIDENCE_TYPES`、`SUPPORTED_TYPES`、`GD_VERSION` |

## 2. Python API 用法

```python
from modules.bio_analysis_function.common.genome_diff import (
    format_genome_diff,
    read_genome_diff,
    write_genome_diff,
)

diff = read_genome_diff("output.gd")

diff.header.value_of("PROGRAM")            # 'breseq 0.33.1 revision 8505477f25b3'
diff.header.values_of("READSEQ")           # 两个 read 文件的路径
diff.header.value_of("MAPPED-BASES")       # '434491437'

for record in diff.mutations():            # 只看突变；RA / MC / JC 是证据，不在里面
    print(record.type, record.position, record.fields, record.frequency)
    # SNP 1269450 ('T',) 0.104…

del_record = diff.by_id("2")
diff.evidence_of(del_record)               # 顺着编号取回它引用的证据记录

text = format_genome_diff(diff)            # 正常文件与原文逐字节一致
write_genome_diff("copy.gd", diff)         # 写文件，返回记录条数
```

写出我们自己的结果（一条替换 + 支持它的 read 证据）：

```python
from modules.bio_analysis_function.common.genome_diff import (
    MutationEntry,
    assemble_diff,
    read_alignment_evidence,
    substitution_record,
)

diff = assemble_diff(
    [
        MutationEntry(
            mutation=substitution_record(          # SNP：新碱基 + 频率
                seq_id="NC_001422", position=1234, call_base="T", frequency=0.98,
                attributes=(("gene_name", "geneX"),),   # 注释信息由注释模块算好后填进来
            ),
            evidence=(
                read_alignment_evidence(           # RA 证据：偏移、参考碱基、判定碱基 + 统计量
                    seq_id="NC_001422", position=1234,
                    reference_base="C", call_base="T", frequency=0.98,
                    consensus_score=133.2, prediction="consensus",
                ),
            ),
        ),
    ],
    header_entries=(("PROGRAM", "Project IDEA bio"), ("REFSEQ", "NC_001422.gbk")),
)
# 编号由装配器分配：突变 1..N、证据 N+1..M；输出顺序是先全部突变、再全部证据
```

**时间戳不自动写**：上游有 `#=CREATED`，但自动写当前时间会让同样输入产出不同文件（不可复现）。
要写就自己给一条 `("CREATED", "...")`。

比较多份样本（"哪些突变是共有的、哪些是新出现的"）：

```python
from modules.bio_analysis_function.common.genome_diff import compare_files

table = compare_files([("0K", "output_0K.gd"), ("10K", "output_10K.gd"), ("40K", "output_40K.gd")])

table.shared()                 # 出现在多个样本里的突变
table.unique_to("40K")         # 只在 40K 出现的新突变
table.rows_of("10K")           # 10K 里出现过的全部突变
row = table.rows[0]
row.key.position, row.samples, row.frequencies, row.first_sample   # 最早出现在哪个样本
print(table.to_csv())          # 一行一条突变、一列一个样本（单元格是该样本里的频率）
```

把某一代的突变贴回参考，得到那一代的基因组：

```python
from modules.bio_analysis_function.common.genome_diff import apply_diff, read_genome_diff

applied = apply_diff({"NC_001422": reference_sequence}, read_genome_diff("output_40K.gd"))
applied[0].sequence        # 突变后的序列（可直接写成新的 FASTA）
applied[0].length          # 原长 + 插入 − 缺失
for item in applied[0].mutations:      # 每条突变在新序列里的位置（上游 0.37 也给了这个能力）
    print(item.record.type, item.record.position, "→", item.position, item.shift)
```

## 3. 格式要点（都对着真实产物核过）

记录行的列：**类型、编号、证据编号列表、参考名、位置**，之后是"类型特有字段"与 `key=value`
属性。各类型的特有字段（取自真实文件、并用同目录的 `index.html` 交叉验证）：

| 类型 | 特有字段 | 含义 |
| --- | --- | --- |
| `SNP` | 1 个：新碱基 | `SNP 5 37 NC_000913 1269450 T` → html 那一行写的是 `C→T` |
| `DEL` | 1 个：缺失长度 | `DEL 2 35 NC_000913 701810 1` → html 写 `Δ1 bp` |
| `INS` | 1 个：插入的碱基 | `INS 4 74 NC_000913 1159282 AGT` → html 写 `+AGT` |
| `MOB` | 3 个：元件名、链、长度 | `MOB 7 72,77 NC_000913 1293032 IS1 -1 8` → html 写 `IS1 (–) +8 bp` |
| `RA` | 3 个：偏移、参考碱基、判定碱基 | `RA 37 . NC_000913 1269450 0 C T` |
| `MC` | 3 个：区间终点、长度… | `MC 62 . NC_000913 1299499 1300697 1198 0` |
| `JC` | 多个：另一侧参考名/坐标/链… | `JC 69 . NC_000913 1 1 NC_000913 4641652 -1 0`（跨复制原点的连接） |

三条规矩：

1. **不认识的类型与属性一律保留**。格式里可选属性很多（`frequency`、`prediction`、
   `polymorphism_score`、`major_base`…），breseq 各版本还会增删；因为"不认识"就丢掉，
   等于把产物改坏。所以类型是字符串、属性是保序键值表，**没有白名单**。
2. **证据编号列**：突发行里是编号列表（`61,71`，一条突变可能同时有覆盖度缺失与新连接两类证据），
   证据行里写作 `.`。`.` 解析成空元组，写回时还原成 `.`。
3. **坐标一定是整数**，放在固定的第 5 列（1-based）；范围、另一侧坐标都放类型特有字段里。
   位置不是整数时**报错并给出行号**，不猜着解析。

**写出时照上游的三条规矩**（同样从真实产物反推，因此我们的突发行能与它逐字节相同）：

1. **编号与顺序**：突发行占 `1..N`、证据行接着占 `N+1..M`，**输出时先全部突变、再全部证据**
   （真实文件里突变占 1–34、证据从 35 开始）。`assemble_diff` 按这个规矩编号，并回填每条突变
   行里的证据编号列。
2. **证据行的"偏移"列**：替换写 `0`；插入的第 1、2 个碱基写 `1`、`2`，且参考碱基那一列写 `.`
   （真实文件里 `RA 58 … 1 . C` 与 `RA 59 … 2 . G` 就是一次插入的两个碱基）。
3. **频率的写法**：恰好等于 1 时写 `1`，其余写 8 位小数的科学计数（`1.16257668e-01`）。
   数值与写法无关，消费者应按数值解析；但对得上写法意味着我们能和上游产物逐字节比对。

**应用突变时三类突变的语义**（`apply_mutations` / `apply_diff`）：

| 类型 | 语义 | 长度变化 |
| --- | --- | --- |
| `SNP` | 位置 `p` 的碱基换成记录里的新碱基 | 0 |
| `DEL` | 从 `p` 起删掉 `length` 个碱基（**含 `p` 自己**） | −`length` |
| `INS` | 在 `p` **之后**插入记录里的碱基（即插在 `p` 与 `p+1` 之间） | +插入长度 |

`DEL` 从 `p` 开始这一条有旁证：真实产物里 `DEL 2 … 701810 1`（Δ1 bp）对应的证据是
`RA 35 … 701810 0 A .`，参考碱基正是 `A`——被删掉的就是 701810 这个碱基。`INS` 的"插在 `p`
之后"是**我们的读法**（待与上游逐条核对，见待办）。应用时**按坐标从后往前改**，位置 `p` 在新
序列里的坐标 = `p` + 所有坐标更小的突变的长度增减之和（`INS` 再 +1）；同位置的多个突变按传入
顺序依次应用。

## 4. 参数与约定

| 项 | 说明 |
| --- | --- |
| 字段与属性的分界 | 取**第一个含 `=` 的列**：之前的算类型特有字段，之后的算属性。真实产物里每个类型都符合（`frequency=`、`alignment_overlap=`、`left_inside_cov=` … 都是属性段第一个） |
| 属性段里的裸词 | 读作"键、值为空"，写回成 `键=`。**一个 `=` 都没出现**时，后面的裸词按字段处理——这是格式本身的歧义（真实产物不会走到这一步），有测试钉住 |
| `#` 开头但不是 `#=` 的行 | 当作注释**原样保留**，写回时照抄（手写的 `.gd` 里可能有） |
| 行尾与空行 | 兼容 CRLF（读入自动归一）、写出一律 LF；空行丢弃。正常文件因此能逐字节往返 |
| 缺版本行 | 用默认版本 `1.0`，写回时补上（格式要求第一行是它） |
| gzip | **不做**。`.gd` 是文本小文件（真实样例十几 KB），压缩由外层决定；参考文件那边需要解压是因为它可能几百 MB |
| 注释 | **不做**。`gene_name` / `gene_position` / `gene_product` 这些属性由突变注释模块算好后填进来，本层只管格式 |
| 比较：同一条突变的判定 | **类型 + 参考名 + 位置 + 类型特有字段**都相同（`SNP` 看新碱基、`DEL` 看长度、`INS` 看插入序列）。所以同一位置上的 `A→C` 与 `A→G` 是两条突变，各占一行。注意 `SNP` 行本身不带参考碱基（参考是固定的），身份键里也就没有它 |
| 比较：谁参与 | 只比较**突变行**。`RA` / `MC` / `JC` 是证据，同一突变在不同样本里的证据行本来就可能不同，拿来对齐没有意义 |
| 比较：行序 | 按（参考名、位置、类型、类型特有字段）升序——确定性优先，便于两份表做 diff |
| 比较：CSV 单元格 | 写**该样本里这条突变的频率**（各样本各写各的）；没出现就留空；出现但拿不到频率（没写这个属性或写了 `NA`）写 `NA` |
| 应用：支持的突变 | `SNP` / `DEL` / `INS`（`SUPPORTED_TYPES`）。`MOB` / `AMP` / `CON` / `INV` 不能靠"改一段序列"实现（要动整条序列的结构），报错说明；证据行也不能拿来应用 |
| 应用：越界 | **跨过参考末端的缺失直接报错**——环状参考上跨复制原点的缺失是合法突变，但这一版没做环绕，报错比静默截断好。位置越界同样报错 |
| 应用：先校验后执行 | 所有突变先整体校验，有一条不合法就整体报错，不产出"改了一半"的序列 |
| 应用：未触及的参考 | `apply_diff` 把**给定集合里每条序列都返回**（没被碰到的原样返回），方便直接写新的参考文件；突变指向集合外的参考名时报错，免得被静默丢掉 |

## 5. 怎么跑测试

```bash
python -m pytest modules/bio_analysis_function/common/genome_diff -q
```

**70 项**全过（模型 7 + 解析与写回 13 + 构造与装配 15 + 比较 16 + 应用 19）。五组各有最硬的一条：

- **解析**：`test_real_sample_round_trips_byte_for_byte`——把真实产物的一段（13 行头 + 9 条
  记录，覆盖 DEL / INS / SNP / MOB 四种突变与 RA / MC / JC 三种证据）**内嵌在测试里**，
  解析完再写回，要求与原文**逐字节相同**。内嵌而不落盘成数据文件，一是它够小（十几行），
  二是不把外部数据混进仓库（算法清单 5.3 对数据登记有要求）。
- **构造**：`test_substitution_record_reproduces_the_real_line` 等四条——用真实行里的数值构造
  记录，输出与真实行**逐字节相同**（`SNP 5 37 NC_000913 1269450 T frequency=1.04031563e-01`
  等）。这证明我们写出来的东西上游工具能直接读，而不是"看起来像"。
- **装配**：编号（突变 `1..N`、证据 `N+1..M`）、输出顺序（先突变后证据）、证据列回填、
  以及"写出去再读回来相等"的往返。
- **比较**：同一位置不同碱基 / 不同插入序列 / 不同缺失长度都算**不同**突变（这是比较的地基，
  单独钉了三条）；各样本的频率**不会串**（代表记录的频率与逐样本频率分开存）；证据行不参与；
  行序确定；CSV 的样本列、空单元格与 `NA`、含逗号的字段会加引号；最后是"用分片 B 造两份 `.gd`
  写盘再读回来比"的端到端用例。
- **应用**：三类突变各自的语义（替换、从 `p` 起删、插在 `p` 之后）；**三条突变混在一起**的用例
  最吃功夫——手算好最终序列 `AAGGACGGGATT` 与每条突变的新位置/位移，顺序或位移写错它必挂；
  还有"缺失让后面的坐标左移"、同位置两条按传入顺序应用、跨末端缺失报错、不支持的类型报错、
  证据行报错、越界报错、**有一条不合法就整体不执行**，以及从分片 B 造的 `.gd` 端到端应用。

其余用例覆盖：四种突变类型的特有字段与证据编号、证据行的 `.`、跨参考的连接记录、
属性保序与未知键、`frequency=NA`、注释行与 CRLF、缺版本行、裸词歧义（两种情形）、
行数不足与位置非整数的报错（都要求带行号）、写文件再读回、构造参数的校验
（位置 / 碱基 / 频率取值范围 / 缺失长度 / 插入序列）、头信息顺序与双端 `#=READSEQ`。

## 附：设计记录

### 上游是什么（带出处）

breseq 每次跑完都会写出 `output/output.gd`（HTML 报告里 "genome diff" 那个链接就是它）。
上游描述它是"制表符分隔的文本，每行描述一个突变或一条支持突变的证据"；格式的完整说明在上游
源码附带的文档里（参考文献：Deatherage & Barrick, *Methods Mol Biol* 2014）。

**本项目的做法是"看真实产物定格式"**：从一份公开的 breseq 0.33.1 输出（aledb.org 的 ALE 数据库，
pgi 进化实验）取真实文件，再对照同目录的 `index.html`（人读版报告）核对每一列——例如
`SNP 5 37 NC_000913 1269450 T` 对应 html 里的 `C→T`，这一步确认了"SNP 的第 6 列是新碱基"。
这样定下来的格式不会掺进我的印象，也能在文档里指出每一列的出处。

### 已定的实现取舍

- **属性不设白名单、保序保存**：模型里属性就是"保序的键值表"，连值都保持字符串原样
  （`1.16257668e-01` 不转成浮点再写回——那会改变字节）。数值化只在你主动要的时候发生
  （`record.frequency`）。这样才能做到逐字节往返。
- **`frequency` 给一个数值便捷访问**：上游会写 `frequency=NA`（连接记录在无法估计时），
  这时返回 `None` 而不是抛异常——"不知道"是合法状态。
- **位置用 1-based 整数、范围放字段里**：与 `reference_io` 的坐标口径一致；也让"哪一列是位置"
  这件事在模型里是明确的（不是靠约定记住）。
- **解析器只做格式层**：不校验"SNP 的记录是否真有证据"之类语义（上游也会写出人工整理过、
  证据被删掉的行）；语义检查留给用它的那一步。
- **逐字节往返作为硬指标**：产物契约的价值在于"能被别人原样接着用"。改一个字节都可能让
  上游工具或下游脚本不认。这条在分片 B 又用了一次：构造出来的行要和真实产物**逐字节相同**。

**分片 B（构造）另加的取舍：**

- **只吃纯数据，不认识算法层**：构造函数收的是位置、碱基、频率这类基本值，"哪条调用对应哪条
  记录"的胶水留给编排层（公共层 import 子模块是禁止的，见 `开发规则.md` 3.1）。这样也能直接
  给外部结果用——比如把别的工具算出的替换套进同样的 `.gd` 写法。
- **编号由装配器分配，不让调用方填**：编号必须与证据编号协调（突变 `1..N`、证据接着编），
  让调用方手工填是最容易错的一环。构造函数产出的记录 `id` 是空的，装配时统一覆盖。
- **头信息不自动写时间戳**：上游有 `#=CREATED`，但自动写当前时间会让"同样输入两次跑出不同
  文件"，与可复现的要求冲突。要写就显式给。
- **只做 RA 证据线能产出的三类突变**（`SNP` / `DEL` / `INS`）。`MOB` / `AMP` / `CON` / `INV`
  依赖 `JC` / `MC` 两条证据线，那两条线本项目还没做，现在做它们的构造函数是空转。
- **注释属性不替上游命名**：上游突发行里我们只确证过 `frequency` 一个属性，所以本层不擅自
  发明 `gene_name` 之类的键——注释信息由调用方通过 `attributes` 传进来，键名由用它的那层定。

**分片 C1（比较）另加的取舍：**

- **只对齐语义，不假装复刻上游的列**：上游 `gdtools COMPARE` 支持 HTML 与 TABLE（CSV）两种
  输出，``-b`` 还会多带 `TEXT_*` 列；我们没见过它 TABLE 的真实输出，所以列序与单元格写法是
  **我们自己定的明确口径**，写进文档、写进测试。真要和上游逐列对齐，得先拿到一份它的 TABLE
  输出（记在待办）。
- **"同一条突变"用"类型 + 参考名 + 位置 + 类型特有字段"判定**：这是唯一能从 `.gd` 里客观
  得到的身份。注意这条判定的后果——同一位置的不同碱基是两条突变。如果下游想按"位置"合并，
  那是它们的策略，不该由本层替它决定。
- **证据行不参与比较**：把 `RA` 行也拿来对齐会得出"同一突变在不同样本里不一样"的荒谬结论。
- **每行的频率逐样本存**（`frequencies`），代表记录只用于携带属性/注释：一开始我把频率放在
  代表记录上，写 CSV 时才发现"晚期样本那一格会写成早期样本的频率"——这类串味是静默的，
  所以结构上直接分开。
- **行序确定**：按（参考名、位置、类型、字段）升序。比较表的用途之一是两份表做 diff，
  顺序不确定会让 diff 全是噪声。
- **同一份样本名重复时报错**：不报的话"哪个样本里有这条突变"就没法说明白。

**分片 C2（应用）另加的取舍：**

- **"应用后的位置"一起给**：上游 0.37 才加上这个能力，但它其实是刚需——更新完参考序列之后，
  "这条突变现在在哪"是下一步（重新比对、看覆盖度、画图）都要用的。所以 `AppliedGenome` 里带着
  `(原坐标, 新坐标, 位移)`。
- **位移用前缀和算，不边改边记**：每条突变先算长度增减、再算"坐标更小的突变的增减之和"，
  最后按坐标**从后往前**改序列。边改边记坐标是这类实现最容易出错的地方（改一次就得重算所有
  后面的坐标）。
- **先整体校验再动手**：有一条越界或类型不支持就整体报错，不返回"改了一半"的序列。
- **跨末端的缺失明确报错，不支持跨复制原点**：环状参考上跨原点的缺失是真实存在的突变类型，
  我们的参考读取分得清环状，但这一版没做环绕拼接。报错并说明原因，比静默截断（凭空丢一段）
  安全得多。
- **不支持 `MOB` / `AMP` / `CON` / `INV`**：它们不是"改一段序列"能表达的（要动整条序列的结构，
  比如倒位、拷贝数变化），硬做只会做出看起来对、其实错的结果。报错说明，留给将来。
- **`apply_diff` 返回集合里每条序列**（没被碰到的原样返回）：调用方直接拿去写新的参考文件，
  不必自己拼接"哪条变了、哪条没变"。突变指向集合外的参考名时报错，不静默丢。

### 已知限制与待办

- **`INS` 的插入点语义待与上游核对**：我们按"插在 `p` 之后"实现（`p` 是插入点前那个碱基）。
  这是从真产物的形态推的读法，**没有**用"参考 + 突变后序列"逐条核过；真要拿我们的应用结果
  与上游 `gdtools APPLY` 的输出逐字节比，先核这一条（`DEL` 的"从 `p` 起删"有旁证，见第 3 节）。
- **不支持跨复制原点的突变**：环状参考上跨原点的缺失/插入会越界报错。要支持得先把序列接成环
  再切回线性，"环绕补齐"的坐标语义要单独设计——留给将来（上游 0.37 修过这里的崩溃）。
- **`MOB` / `AMP` / `CON` / `INV` 不能应用**：它们要动整条序列的结构（倒位、拷贝数变化），
  不是"改一段"能表达的。本层报错说明，不做半成品。
- **上游 `gdtools` 的其它子命令没做**：`SUBTRACT` / `INTERSECT` / `UNION`（`MERGE`）/ `FILTER`
  与格式转换（`GD2VCF` / `VCF2GD` / `GD2GVF`）。其中 `SUBTRACT` 与 `INTERSECT` 用现在的
  `ComparisonTable` 就能拼出来（"只在一份里"与"共有"），等真有需求时再加薄薄一层。
- **比较表的列序与上游未对齐**：上游 `COMPARE` 的 TABLE 输出我们没见过，所以列序、单元格写法
  （它可能写别的标记而不是频率）都以我们的口径为准；语义（一行一条突变、一列一个样本）一致。
- **不统计频率的演化**：比较只回答"有没有"，顺带带上各样本的频率数值；不回答"频率是不是显著
  上升"这类问题（那是统计层的事）。
- **三种突变类型以外的没做**：`MOB`（可移动元件插入）/ `AMP` / `CON` / `INV` 依赖 `JC` / `MC`
  两条证据线，本项目还没做那两条线。真要做时，往 `build.py` 加构造函数即可（字段规则可以
  照真实产物核）。**注意**：这些类型读得进来（分片 A 不设白名单），也能参与比较（身份键是通用的），
  只是不提供构造函数。
- **注释属性的键名待与上游核对**：上游突发行里我们只确证了 `frequency`；如果将来要和上游
  产物做逐字段对拍，得先确认注释属性的命名（`gene_name` 之类）到底怎么写。
- **证据行的类型特有字段只按"事实"保存，不做语义解释**：例如 `MC` 的第 3、4 个字段
  （`1198 0`）与 `JC` 的一长串属性（`pos_hash_score`、`side_1_*` …）都是上游内部量，
  本层不解释它们，也不根据它们做判断。
- **不支持"非 breseq 风格"的 `.gd` 扩展**：如果将来要写自定义属性（我们可以自由加 `key=value`），
  读回时会被当成未知属性原样保留 ✓；但若自定义成"没有固定第 5 列位置"的形式，读不了。
- **gzip 与 BOM 未处理**：`.gd` 一般不大；真遇到压缩文件由外层解压再来读。
