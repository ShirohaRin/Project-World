> 上一版 v0.53（**共识碱基调用补齐多态档（分片 E）**：`submodules/consensus_calling/polymorphism.py`
> ——混群体里"只有一部分 read 支持"的少数派碱基。**关键判断：多态档不能沿用共识档的判据**。
> 上游 `prediction=polymorphism` 报的常是少数派（真实产物频率低到 7%–12%，例
> `RA 37 … 0 C T frequency=1.04031563e-01`），而"最佳碱基与参考不同"永远看不到它——少数派的
> 似然必然低于参考。改用**混合模型**：`P(obs) = f·P(b|X,q) + (1−f)·P(b|R,q)`，对 `f` 在 0.01 步长
> 网格上取最大似然得 `f̂`，比值对的是**纯参考解释** `L(f=0)`，`score = log₁₀[L(f̂)/L(f=0)] − log₁₀(参考总长)`
> （折减口径与共识档一致，但**两档 score 不可直接互比**）。两档按 `f̂` **互斥**：`≥0.8` 归共识档、
> `[0.05, 0.8)` 归多态档、`<0.05` 不报；多态档先跑一次 `score_position` 做归属检查。
> **三个默认阈值（0.05 / 0.8 / 3.0）是我们的取值**：上游那一档还带 `bias_p_value` /
> `fisher_strand_p_value` 统计检验，**没有复刻**，故门槛显式留成参数并如实标注差异。
> 本模块 **63 项**测试（新增多态档 12）、`submodules` **626 项**全过\

## 1. 文档目的与边界

本清单用于定义后续要实现的生物算法能力，而不是把所有算法一次性全部实现。每个条目后续应进一步补充：输入数据格式、参数约定、统计假设、输出对象、可视化、可复现性要求、适用场景、测试数据和参考实现。

Majorbio 云工具与云流程作为重要的产品形态参考。其公开页面已经覆盖表格/数据处理、多元统计、可视化、序列与文件处理、ID 转换、统计分析、序列比对、基因注释与分类、基因集分析、定量分析、生存分析、基因/数据评估、分子生物学、单细胞分析、基因组浏览器和同源比对等类别，并提供微生物、DNA、转录与调控、蛋白组、代谢组、单细胞空间组、多组学关联等流程。

本项目不应只复制网页工具，而应把方法整理为可组合的算法服务：数据质控 → 预处理/归一化 → 特征提取 → 统计建模或机器学习 → 多重检验 → 注释与解释 → 可视化 → 结果验证。

## 2. 优先级与覆盖标记

- **P0：基础能力**：高频、跨组学复用、适合先实现并建立测试基线。
- **P1：核心组学能力**：常见科研分析中高频使用，作为主体功能。
- **P2：扩展能力**：专业场景、复杂模型或计算成本较高，按需求实现。
- **P3：研究型能力**：前沿方法、强依赖外部数据库/模型或需要专门评测，先保留接口和实验性实现。
- **M：Majorbio 已有同类工具或流程**：可作为交互和结果展示参考，不代表算法实现细节完全相同。
- **A：建议新增/重点补充**：在 Majorbio 公开工具目录中没有明显对应项，或需要以更完整、现代、可组合的方式补强。

### 5.5.1 上游是什么

[breseq](https://github.com/barricklab/breseq)（官方文档在 `breseq.barricklab.org`）做的是
**单倍体微生物基因组的重测序分析**：reads 比到参考 → 找出与参考不一致的地方 →
判断这些差异意味着什么突变 → 注释到基因 → 出 HTML 报告。官方定位是细菌级基因组
（文档写 <10 Mb），要求样本与参考差异 <1‰。

它内部是 **14 个阶段**（名字取自它自己生成的 `summary.html`）：
读参考与 reads → **bowtie2 比对** → 为 junction 候选预处理比对 → 覆盖度分布预分析 →
找候选 junction → **把所有 reads 重比到候选 junction** → 判定每条 read 的最佳归属 →
写 BAM → 统计错误计数 → **重校准碱基错误率** → 生成 RA 证据 → 多态性统计 →
输出（突变预测 :: 突变注释）。

**四类证据 → 六类突变**：

| 证据 | 含义 | 判出的突变 |
| --- | --- | --- |
| `RA` | read 比对证据（贝叶斯共识打分，E-value = log₁₀L − log₁₀参考总长） | SNP / SUB / 短 INS / DEL |
| `MC` | 缺失覆盖（先拟合负二项覆盖分布，再 seed-and-extend） | 大片段 DEL（与 JC 合力） |
| `JC` | 新 junction（嵌合比对：先找候选、再重比、再打分接受） | INS/DEL/SUB；`JC+JC` → MOB（移动元件插入）；`JC`(+CN) → AMP（扩增） |
| `UN` | 未知碱基（证据不足的区域） | 不产出突变；用于区分"覆盖不足/质量差导致漏检" |

两种模式：**consensus**（默认，纯克隆重测序）与 **polymorphism**（`-p`，混合群体，
极大似然求等位频率 + 似然比检验 + 链偏好/质量偏好/同聚物过滤）。

**依赖与平台**：外部依赖 bowtie2（必需）；v0.40.x 画图用 R、samtools 静态链入，master
反而去掉 R 改用 gnuplot。**官方没有 Windows 支持（只给 WSL）**，这与 5.4 节
"只能自研才能进 win-x64"的判断一致。

### 5.5.2 拆解：14 个阶段落到本模块的三层

| 层 | 承担的东西 |
| --- | --- |
| `common/`（工具与格式 IO） | **参考资料读取**（已完成）、**SAM 读写**（已完成）、**Genome Diff 读写**（`.gd`，已完成，见 6.5 第 6 行）、复用既有的 `fastq.py`；BAM 待做。进度见 6.5 |
| `submodules/`（各自回答一个问题） | ① **read 比对器**（最大件）② 共识碱基调用（含错误率重校准、read 端修剪，以及**并入其中的多态档**）③ 覆盖度与缺失区（MC）④ junction 检测与打分（JC）⑤ 突变注释（同义/非同义、密码子、基因内坐标）——**注**：规划里原单列的"多态性调用"实现时并入了②（同一套堆叠/错误率/裁剪，只换判定模型），故不再单列 |
| 编排层（每个流程各自独立） | 14 个阶段的顺序与参数、**证据 → 突变的规则**、`.gd` 与 HTML 报告（沿用内嵌 SVG 的取舍，不用 R / gnuplot）、日志 |

**突变预测那层不是新算法**——`RA→SNP/SUB`、`MC+JC→DEL`、`JC+JC→MOB`、`JC→AMP` 以及
orphan / marginal 的分流都是固定规则，因此归编排层，不单独做广场入口。

### 5.5.3 四项已定决策（2026-09-23 白羽奈绪拍板）

1. **比对器：自研为主 + 接受外部 SAM/BAM**。自研一个面向细菌级参考的比对器；同时支持把
   外部已比对的 SAM/BAM 喂进来——后者成本很小，却是**与上游做阶段级对拍的唯一手段**。
2. **v1 范围：先做 RA 线**。比对 + 错误率重校准 + 共识碱基调用 + 突变注释 + 报告，
   consensus 模式；MC / JC / MOB / AMP 与 polymorphism 模式留到后续。
3. **验收口径：比突变集合**。用 breseq 官方测试数据比对"预测出的突变集合"（位置、类型、
   新序列一致即通过），允许证据细节（读段数、E-value、junction 打分）不同。
   **不承诺与上游逐位一致**——上游输出里含 bowtie2 的比对选择，除非连比对器也复刻。
4. **落位：每个流程一个 workflow，先把流程里的所有算法做好**。算法与格式 IO 归本模块
   （`submodules/` 与 `common/`），各流程的编排各自独立；本阶段只管把算法做齐做稳。

### 5.5.4 推进顺序

1. **参考资料读取**（`common/reference_io/`）——**已完成**，见 6.5。
2. **SAM 读写**（`common/alignment_io/`）：写，让我们的比对结果能被 IGV 看、能对拍；
   读，接外部比对结果，并用上游跑出的 SAM 做阶段级对拍。——**已完成**，见 6.5。
3. **read 比对器**（`submodules/read_mapping/`）：索引 → 种子 → 扩展 → 多重命中与映射质量 →
   与"从已知参考生成 reads"的合成数据对拍。**这是这条线第一个真正的算法，也是最难的一块。**
   ——**已完成 A–F**：k-mer 种子索引、种子投票与候选对角线、带内比对与 CIGAR、软剪裁与
   末端处理、多重命中/MAPQ 与 SAM 输出、端到端对拍与性能实测（90 项测试、性能基准脚本）。
   遗留：原生移植、算法广场执行链路、与上游工具的互操作验收——见
   [read_mapping.md](./submodules/read_mapping/read_mapping.md) 的「已知限制与待办」。
4. **堆叠与证据表** + **共识碱基调用**（`submodules/consensus_calling/`）：错误率重校准
   （按 参考碱基 × read 碱基 × 质量 计数，pseudocount=1）、贝叶斯共识打分与 E-value、
   read 端修剪、**多态档判定**。——**已完成 A–E**：堆叠（吃 SAM，只在公共层止步，不依赖
   比对器）、错误率重校准、似然比打分与判定（`log₁₀ L − log₁₀ 参考总长` + 默认阈值
   「打分 ≥ 10 且频率 ≥ 0.8」）、read 端裁剪（参考 1–18 bp 完全重复 → 每端至少裁 1）、
   **多态档**（混合模型最大似然，报少数派碱基，两档按 `f̂` 互斥）。63 项测试；合成已知突变的
   数据集上**检出集合与真值集合逐项吻合**。遗留：indel 判定、链偏好/最低覆盖过滤（上游默认关）、
   上游多态档的统计检验（`bias_p_value` 等，未复刻）、原生移植、广场执行链路——见
   [consensus_calling.md](./submodules/consensus_calling/consensus_calling.md) 的「已知限制与待办」。
5. **突变注释**（`submodules/mutation_annotation/`）：密码子翻译、同义/非同义、基因内相对
   坐标、基因间距离——建立在 `reference_io` 的特征表上。——**已完成 A–D**：遗传密码与 CDS
   翻译、变异 → 密码子与氨基酸效应（六种效应取值、重叠基因各一条、负链取互补）、基因间与
   距离（`intergenic (+22/-4)`、符号按转录方向）、端到端注释表（四类分类 + TSV）。62 项测试；
   真实参考 phiX174 上三处硬证据（11 个 CDS 与 NCBI 的 `/translation` 逐条相等、每个 CDS
   造替换都落回同一基因、全部 5386 个位置全扫描：编码区占比 95.97%、1392 个重叠位置）。
   遗留：indel 判定、广场执行链路、非标准遗传密码表——见
   [mutation_annotation.md](./submodules/mutation_annotation/mutation_annotation.md) 的「已知限制与待办」。
6. **覆盖度与缺失区（MC）**（`submodules/missing_coverage/`）：逐位覆盖深度 → 负二项拟合 →
   低覆盖阈值 → seed-and-extend 找缺失区。——**已完成 A–C**：覆盖剖面（差分数组直接吃 SAM，
   只看 unique 比对）、负二项矩估计与阈值（左尾 α = 0.05/√L）、缺失区检测（零覆盖种子 +
   向两侧扩展）。34 项测试；合成"整段被删"的数据上缺口边界逐位吻合。遗留：`MC` 证据行构造与
   与真实产物的字段核对、`MC + JC → DEL` 的判定（编排层）、原生移植——见
   [missing_coverage.md](./submodules/missing_coverage/missing_coverage.md) 的「已知限制与待办」。
7. **junction 检测与打分（JC）**（`submodules/junction_calling/`）：>2 bp 空位拆子比对 →
   五条判据挑嵌合对 → 拼连接序列 → 位置哈希分与最小重叠分排序截断 → 四条支撑判据接受。
   ——**已完成 A–C**：分段与候选对、打分与排序、接受判据（47 项测试）。这是**结构变异**那条线
   （`JC + JC → MOB`、`JC → AMP`、`JC + MC → DEL`）。遗留：**重比**（把 read 再比到候选连接上，
   只增加敏感度，留给编排层接通时做）、上游 skew 分位阈值（零假设未公开，改用位置哈希分下限）、
   分片 D `JC` 证据行、反转类连接、重叠区修剪、`repeat_region` 边界偏好——见
   [junction_calling.md](./submodules/junction_calling/junction_calling.md) 的「已知限制与待办」。
8. **`.gd` 读写**（`common/genome_diff/`）：产物契约，也是将来做 gdtools 等价物的基础。
   ——**四片全部完成**（A 格式模型与解析 / B 从结果构造 / C1 比较多份 / C2 给参考应用突变，
   70 项测试）：格式照着真实 breseq 产物定、逐字节往返；构造出的突发行与真实产物逐字节相同；
   比较多份 `.gd`（对应 `gdtools COMPARE` 的语义）；应用突变产出新序列与每条突变的新位置
   （对应 `gdtools APPLY`，`INS` 的插入点语义标注为待核）。跨复制原点、`MOB`/`AMP`/`CON`/`INV`
   的应用、其它 gdtools 子命令未做，见
   [genome_diff.md](./common/genome_diff/genome_diff.md) 的「已知限制与待办」。
9. **编排与报告**（`modules/workflow/breseq/`，能力层）：把上面这一串按上游顺序串成流程。
   ——**开工，RA 线端到端打通**（15 项测试）：读参考 + 扫 FASTQ（阶段 A）→ 比对并写 SAM →
   read 端裁剪 → 错误率重校准 → 共识档/多态档调用 → 证据→突变（RA 线的固定规则）→ 突变注释 →
   写 `.gd` + 注释表 + 摘要表。**它不是单遍流程**：比对落盘成 SAM，后续步骤都从 SAM 走
   （规模 + 接受外部 SAM/BAM 两条理由）。遗留：MC / JC 接入、报告层（HTML + JSON）、
   `wrapper.py`、广场契约与预设队列——见
   [breseq_workflow.md](../workflow/breseq/breseq_workflow.md) 的「已知边界」与「开发记录」。

**覆盖度与缺失区（MC）**（第 7 行）推进到**分片 C 完成**：这是 `RA` 线之外的第一条新证据线
（`MC` = missing coverage），负责"整段没有 read"这类证据——大片段缺失。三片：**A 覆盖剖面**
（`profile.py`）不复用共识调用的堆叠，而是**直接从 CIGAR 摊差分数组**（`M`/`=`/`X` 给
`[起点, 终点)` 加一，最后前缀和）——覆盖度只需要"每个位置被多少条 read 盖住"，比逐个观测建对象
省得多；只数 **unique** 比对（`mapq ≥ 1`），`D`/`N`/`S` 都不贡献覆盖。**B 分布与阈值**
（`distribution.py`）按**矩估计**拟合负二项（`r = μ²/(σ²−μ)`；`σ² ≤ μ` 时退回泊松），
阈值取**左尾概率 = 0.05/√L** 的深度（`L` 是这条参考序列的长度，乘 `sqrt(L)` 是把多重比较折进去）。
**C 缺失区检测**（`missing.py`）把上游那句"以无覆盖处为种子、向两侧扩展穿过低覆盖区"写死成
一句话：**连续的深度 ≤ 阈值的位置，其中至少含一个零覆盖位置的才报**（种子的硬信号是"一条 read
都没有"）；报出的区间带四个边缘深度（`left/right_inside/outside_cov`），与上游证据行的同名属性
对齐。34 项测试；合成"整段被删"的数据上缺口边界逐位吻合。**未做**：`MC` 证据行的构造与真实
产物的字段核对（`MC 62 . NC_000913 1299499 1300697 1198 0` 里 `end` 与 `size` 的口径还没定死）、
`MC + JC → DEL` 的判定（属编排层）、原生移植。

**junction 检测与打分（JC）**（第 8 行）推进到**分片 C 完成**：这是**结构变异**那条证据线
（`JC + JC → MOB`、`JC → AMP`、`JC + MC → DEL`），也是 MC 之外第二件"证据需要自己找"的活。
三片：**A 分段与候选对**（`segments.py` / `candidates.py`）先把 **> 2 bp 空位**的比对拆成子比对
（上游的预处理，理由是长空位在简单重复附近本来就不稳），再对一条 read 的多段比对逐对套上游
**五条判据**——首碱基起、两段合起来比**最好的一段**多出 2 bp 以上、两段各 ≥5 bp 独有、
其中一段 ≥10 bp 独有、中间最多夹 20 bp；拼出的**候选连接序列**是"左段贴断点的参考碱基 +
中间那截只属于 read 的碱基 + 右段从断点起的参考碱基"，两端各留**整个数据集最长 read 的长度**
作上下文。**B 打分与排序**（`scoring.py`）用上游的两个分数：**位置哈希分** = 支撑 read 的
**不同起点数**（同位置压过来的一堆 read 只算一个）、**最小重叠分** = 每条 read 两侧独有碱基数
较小值之和（并列时的第二键）；按上游写明的两条上限截断：累计连接长度 ≤ **0.1×参考总长**、
候选数 ≤ **5000**。**C 接受判据**（`acceptance.py`）照抄上游四条支撑判据——两条链都有 read /
有 read 在两侧各延伸 ≥14 bp / **每条链上**有 read 在两侧各延伸 ≥9 bp / 有 read 的较短一侧也
延伸 ≥3 bp；"延伸多少"直接用嵌合对里那两个"该侧独有碱基数"，不再解析二次比对的坐标。
判定结果把中间量全摊开，`failures` 里能看出是哪条判据没过——**没过的原因要能解释，不是悄悄丢掉**。
47 项测试；合成"25 条起点各异、跨同一个 3 bp 缺失"的 read 上候选合并成 1 条、位置哈希分正好 25、
最长延伸 20，且"全是正链"会被两条链的判据挡下。**未做**：分片 C 里的**重比**（把所有 read 再比到
候选连接序列上重新分配支撑 read，作用是提高敏感度，需要比对器注入，留给编排层接通时做）、
上游 `neg_log10_pos_hash_p_value`（skew，零假设没公开；改用位置哈希分下限 3，字段写 `NT`）、
分片 D `JC` 证据行（那串数字里哪几个是两段坐标、`-1`/`0` 是什么还没定死，与 MC 同一条纪律：
口径没定死前不开写）、反转类连接（两段不同链直接报错）、重叠区修剪、`repeat_region` 边界偏好。

## 7. 每个算法服务的最低交付标准

- 明确输入：数据类型、矩阵方向、单位、分组信息、协变量和最小样本条件。
- 明确假设：独立性、分布、方差、测量层级、组成型约束和批次结构。
- 明确输出：统计量、效应量、置信区间、p 值、校正 p 值、图表和机器可读结果。
- 支持可复现：参数保存、随机种子、版本信息、运行日志和中间结果血缘。
- 支持质量控制：输入检查、方法适用性警告、异常结果提示和失败原因。
- 支持证据解释：数据库版本、注释来源、参考文献、方法局限和结果不可推断的内容。
- 具备测试：小型确定性数据、边界数据、缺失/异常数据和至少一个真实公开数据集。

## 9. 当前结论

Project IDEA 的生物方法模块不应被定义为若干孤立的“PCA/聚类工具”，而应建设一个覆盖通用统计、序列与基因组、转录调控、微生物组、蛋白代谢组、单细胞、空间组学、多组学整合、临床预测和结构生物信息学的可组合算法层。

Majorbio 适合提供高频工具分类、流程组织和用户交互方面的参考；Project IDEA 的差异化重点应放在统计假设透明、复杂实验设计、现代单细胞/空间组学、多组学整合、可复现性、证据追踪和算法结果质量评估上。
