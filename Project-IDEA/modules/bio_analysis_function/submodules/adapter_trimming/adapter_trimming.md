# adapter_trimming：reads 接头裁剪

把接头从 read 上剪掉，**FASTQ 进、FASTQ 出**。算法与 fastp 1.3.x 的
`AdapterTrimmer::trimBySequence` / `trimByMultiSequences` 逐位对齐。

本子模块**可独立使用**：在 IDEA Assistant 的生物计算方法广场中有独立入口
（方法 id `bio-adapter-trimming`）。**只需要一份 FASTQ 本身就能运行**——
不需要参考基因组、注释文件或数据库，也不要求先跑别的算法。

---

## 1. 它解决什么问题

测序文库的片段两端连着**接头**。当插入片段比读长还短时，read 的 3' 端会带上一段固定的
接头序列；它会被比对软件当成基因组序列去比、也会干扰组装与去重。所以要把这段切掉。

难点不在"切"，而在**怎么算找到了接头**。四种情况都要照顾到：

| 情况 | 做法 |
| --- | --- |
| 测序错误 | 比对长度**每 8 个碱基允许 1 个错配** |
| read 开头少了接头的前几个碱基（接头二聚体，A-tailing 的后果） | 扫描**从负位置开始**，允许把接头开头跳过去 |
| read 中间多/少一个碱基（测序插入或缺失） | 再试一遍"允许 1 个插入"和"允许 1 个缺失" |
| read 整条都是接头 | 切点落在负位置 → read 被清空 |

**切点之后的部分全部丢弃**（上游不做"只切接头那一段"的精细处理，因为接头之后本来
就不该有基因组序列）。

### 接头从哪来：三种"接头来源"

| 模式 | 对应 fastp | 说明 |
| --- | --- | --- |
| **手动指定** | `--adapter_sequence` | 直接给一条接头序列。**最可靠、推荐**——接头取决于试剂盒 |
| **候选表** | `--adapter_fasta` | 给一组候选依次尝试；公共层内置的 234 条已知接头表也能当候选表 |
| **自动检测** | `--adapter_sequence=auto` | 先调用公共层的接头检测（`common/adapter_detection/`）从数据里找出接头，再按它裁剪 |

自动检测用到的检测能力是**工具**（没有自己的广场入口，见 `开发规则.md` 3.2），
它在这里以"接头来源"选项的形式出现。

## 2. 在算法广场中使用

| 项 | 值 |
| --- | --- |
| 方法 id | `bio-adapter-trimming` |
| 名称 | reads 接头裁剪 |
| 分类 | 序列预处理 |
| 执行方式 | `local` |
| 状态 | `beta` |
| 契约位置 | `IDEA Assistant Code/src/compute.ts` 的 `BIO_ADAPTER_TRIMMING_METHOD` |

**输入字段**：

| 字段 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| reads 文件 | 文本 | 是 | — | 输入 FASTQ（`.fq`/`.fastq`，可 gzip）。当前只处理单端数据。 |
| 输出文件 | 文本 | 是 | — | 结果 FASTQ 的路径。 |
| 接头来源 | 单选 | 是 | 自动检测 | 手动指定 / 候选表 / 自动检测 |
| 接头序列 | 文本 | 否 | — | "手动指定"时填；大写 ACGT，至少 4 个碱基。 |
| 候选接头表 | 文本 | 否 | 内置 234 条已知接头 | "候选表"时填，多行或多条逗号分隔。 |
| 最短匹配长度 | 数字 | 否 | 4 | 接头比它还短就不裁（候选表模式会自动抬高到 5 或 6）。 |
| 允许 1 个插入/缺失 | 开关 | 否 | 开 | 关掉只做等长比对（更严格、更少误伤）。 |
| 输出压缩 | 单选 | 否 | 跟随输入 | 跟随输入 / 强制 gzip / 强制不压缩。 |

**输出**：裁剪后的 FASTQ 文件，外加统计——总 read 数、被裁过的 read 数与占比、
去掉的碱基数、以及**切下来的接头序列**的出现次数（上游把它汇总成"检出了哪些接头"）。

> 界面当前只按 `inputSchema` 渲染表单并创建任务，**实际计算执行链路尚未接通**。

## 3. Python API 用法

```python
from modules.bio_analysis_function.submodules.adapter_trimming import (
    trim_adapter_fastq,
)

# 手动指定（推荐）
summary = trim_adapter_fastq("raw_R1.fastq.gz", "clean_R1.fastq.gz",
                             adapter="AGATCGGAAGAGCACACGTCTGAACTCCAGTCA")
print(summary.render())
# 接头（手动指定）：AGATCGGAAGAGCACACGTCTGAACTCCAGTCA
# 裁过接头的 read：23184（12.34%），去掉碱基 486320
#   · 切下来的 AGATCGGAAGAGCACACGTCTGAACTCCAGTCA：23001 次

# 自动检测（接头未知时）
summary = trim_adapter_fastq("raw_R1.fastq.gz", "clean_R1.fastq.gz", auto_detect=True)
```

单条 read 级接口：

```python
from modules.bio_analysis_function.submodules.adapter_trimming import trim_adapter

result = trim_adapter(sequence, quality, "AGATCGGAAGAGCACACGTCTGAACTCCAGTCA")
if result.trimmed:
    print(result.sequence, result.position, result.removed)
```

## 4. 输出解读

| 字段 | 含义 |
| --- | --- |
| `trimmed_reads` / `trimmed_rate` | 被裁过的 read 数与占比 |
| `trimmed_bases` / `bases_removed` | 去掉的碱基数 |
| `top_adapters` | 切下来的接头序列及其出现次数（最多 5 条） |
| `adapter` / `adapter_source` | 实际使用的接头与它的来源（`given`/`list`/`detected`） |
| `detection` | 自动检测模式下的完整检测结论（含证据） |
| `dropped_reads` | 恒为 0——本算法**不丢 read**（见下） |

**长度被裁到 0 的 read 会原样写出**，`dropped_reads` 也是 0——上游如此：它把"这条 read
该不该丢"留给后面的过滤步骤（长度过滤会按 0 长度丢弃）。若只跑本算法，输出里会看到
空记录，接着接上 reads 过滤即可。

## 7. 已知限制

- **只处理单端 read**。双端数据要靠 overlap 分析找接头，属于后续算法。
- **插入/缺失那两段比对锚定在 read 开头**（上游写法如此）：随扫描位置变的只有比对
  长度，指针并不偏移。后果是**随机 read 的头部偶尔会巧合命中**，于是被切在一个
  偏后的位置——实测 100 条合成数据里出现过 1 次（测试里把该现象钉住了）。
  裁剪的是 read 末尾，通常无害，但这是上游的真实行为，不是本实现引入的。
- **同一处还有一个上游的未定义行为**：``Matcher::matchWithOneInsertion`` 在提前
  ``break`` 之后会读未初始化的数组元素。本实现按它的意图把累计值算完整，因此结果
  确定；只在"上游读到垃圾值"的那些输入上与上游不同（那些情形下上游没有确定行为）。
- **不做去重、不做双端合并**（那是别的子模块的事）。
- **实际计算执行链路尚未接通**，广场入口只到契约层。

#### 5.4.5.1 选择依据

1. **它是"检测"的下游、也是预处理闭环的最后一块**：$5.4.4$ 只回答"接头长什么样"，

   （质量剪切 → poly 修剪 → 接头裁剪 → 过滤），每一步都能独立使用、也能串起来。
2. **它同时是"检测能力"的正式落点**：检测降为公共层工具之后，就是在这里以
   "接头来源"选项的形式暴露给用户（自动检测 / 手动指定 / 候选表）。
3. **上游有可逐行对照的源码与自带测试向量**（`AdapterTrimmer::test()`），
   可以逐位对齐——事实上这次移植就是先让上游向量全过，再补边界用例。

#### 5.4.5.3 问题定义与算法原理

**要照顾的四种情况**（这也是算法的全部难点）：

| 情况                       | 上游做法                                                                                            | 本实现 |
| ------------------------ | ----------------------------------------------------------------------------------------------- | --- |
| 测序错误                     | 比对长度每 8 个碱基允许 1 个错配（$\lfloor c/8 \rfloor$）                                                      | 同   |
| read 开头少了接头的前几个碱基（接头二聚体） | 扫描**从负位置开始**（接头长 $\ge 16$ 取 -4、$\ge 12$ 取 -3、$\ge 8$ 取 -2），负位置时让接头的第 $-pos$ 个碱基对齐 read 的第 0 个碱基 | 同   |
| read 多/少一个碱基             | 等长比对失败后，再试"允许 1 个插入"、"允许 1 个缺失"，两者的容错各减 1                                                       | 同   |
| 整条 read 都是接头             | 切点 $< 0$ → 清空 read，切掉的部分是接头的前 $alen + pos$ 个碱基                                                  | 同   |

**切点之后全部丢弃**：上游不做"只切接头那一段"的精细处理，因为接头之后本来就不该有
基因组序列。

**上游两处必须原样保留的写法**（都写进了测试与 README）：

1. **插入/缺失那两段比对锚定在 read 开头**：循环里随 `pos` 变的只有比对长度
   （$c = \min(rlen - pos - 1, alen)$），指针并不做 `pos` 偏移。后果是随机 read 的
   **头部**偶尔会巧合命中，然后被切在一个偏后的位置（实测 100 条合成数据里出现 1 次）。
2. **`Matcher::matchWithOneInsertion`** **会读未初始化的数组元素**：前缀累计数组在提前
   `break` 之后、后段是未初始化内存，而最后的判定循环在某些输入下会读到它们。
   本实现按它的**意图**把累计值算完整（不提前退出），因此结果确定、可复现；
   只在"上游读到垃圾值"的输入上与上游不同，而那些情形下上游本身没有确定行为。

#### 5.4.5.4 工程实现

- **算法层只做单条 read**（`:func:`trim\_adapter\`\`），文件级接口复用公共层的
  `process_fastq`（分块、压缩、统计与失败清理都一致）；
- **不丢 read**：长度被裁到 0 的原样写出（上游如此，交由后续的长度过滤丢弃），
  因此本算法的 `dropped_reads` 恒为 0，统计里另给被裁 read 数、去掉碱基数与
  **切下来的接头序列**（上游把它汇总成"检出了哪些接头"）；
- **候选表模式的匹配长度自动抬高**：候选 $>16$ 取 5、$>256$ 取 6（上游规则，
  防止候选一多就误伤）；
- **自动检测直接调公共层工具**，不重复实现检测逻辑。

#### 5.4.5.6 适用边界与已知限制

- **只处理单端 read**；双端 overlap 校正与合并、UMI、去重都在别的子模块里实现。
- **插入/缺失分支锚定在 read 开头**（上游写法），随机 read 的头部偶有巧合命中，
  会被切在偏后位置。裁剪的是 read 末尾，通常无害，但这是上游的真实行为。
- **原生层的自动线程数暂取单线程**（写死在 `AutoThreads::Single`）：裁剪是逐位置比对，
  多线程是否有收益尚未实测——要提速的话这是第一个可动的地方。
- **原生层没有"切下来的接头序列"汇总**：那个统计留在 Python 侧（只用于报告，
  不参与判定），因此原生与 Python 对拍时比的是输出字节与通用统计。
- **执行链路尚未接通**，广场入口只到契约层。
