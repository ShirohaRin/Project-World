# consensus_calling：共识碱基调用

从比对结果判定"样本在每个参考位置上到底是什么碱基"，并据此报出与参考不一致的地方。
这是参考比对与变异检测线（breseq 方向）的第四项，也是上游 `RA` 证据线（read alignment
evidence）的核心：**堆叠 → 重校准错误率 → 按似然给分 → 与参考比对后判定**。

> **当前状态：A–E 五片全部完成。** 堆叠 → 错误率重校准 → 共识打分与判定 → read 端裁剪 →
> 多态档判定，碱基替换这条**端到端链路已经跑通**（合成已知突变的数据集上，检出集合与真值集合
> 逐项吻合，精确率与召回率都是 1）。共 **63 项测试**。算法广场入口已登记契约
> （`bio-consensus-calling`，分类「变异检测」，`beta`）——**只登记调用契约、执行链路未接通**，
> 界面会照实提示（见「已知限制与待办」）。

## 1. 现在能做什么

| 项 | 内容 |
| --- | --- |
| 输入 | 一组参考序列 + 比对结果（**SAM 文件路径，或一堆 `SamRecord`**） |
| 输出①堆叠 | 逐参考位置的 `PileupColumn`：该位置的参考碱基、每个碱基观测（read 名、碱基、质量、MAPQ、链方向、在 read 里的下标与读长、**是否落在被裁的末端**）、缺失事件、插入事件 |
| 输出②错误率 | `BaseErrorRates`：经验条件概率 `P(读段碱基 | 参考碱基, 质量)`（五个 read 类别：A/C/G/T + 单碱基缺失），以及入表观测数与各类被排除项的计数 |
| 输出③裁剪 | `ReferenceTrimmer`：参考每个位置"从左端对齐的 read 要裁几个碱基、右端落在该位置的 read 要裁几个"（按需计算 + 缓存） |
| 输出④共识调用 | `ConsensusCall`：报出的**碱基替换**（参考名、0-based 位置、参考碱基、判定碱基、似然比、共识打分、频率、总/支持观测数）；另可用 `score_position` 拿到某位置**全部四个候选碱基**的打分 |
| 输出⑤多态调用 | `PolymorphismCall`：报出的**多态档**调用（`prediction="polymorphism"`，频率落在两个阈值之间）；另可用 `score_polymorphisms` 拿到某位置每个候选碱基的混合模型打分（`PolymorphismScore`） |
| 两档合并 | `call_variants`：一次跑出共识档与多态档，按（参考名、位置）升序，用 `prediction` 区分 |
| 只产出有证据的位置 | 没有证据的位置不产生空列，调用方不必遍历整条参考 |
| 另可用 | `BaseObservation` / `DeletionObservation` / `InsertionObservation`（三类证据的记录类型）、`ConsensusSettings` / `PolymorphismSettings`（两档阈值） |

## 2. Python API 用法

```python
from modules.bio_analysis_function.common.alignment_io import open_sam
from modules.bio_analysis_function.common.reference_io import read_genbank
from modules.bio_analysis_function.submodules.consensus_calling import iter_pileup

reference = read_genbank("NC_001422.gbk")

# 直接吃 SAM 文件（明文或 gzip 都行）
for column in iter_pileup(reference, "mapped.sam"):
    print(column.position, column.reference_base, column.coverage, column.counts())

# 也可以喂已经读好的记录（测试、或从别的来源拼出来的记录）
with open_sam("mapped.sam") as reader:
    columns = list(iter_pileup(reference, reader))

# 没有质量串（QUAL 为 *）时，按 default_quality 处理；默认 0，也就是"当最差的碱基"
columns = list(iter_pileup(reference, "mapped.sam", default_quality=20))
```

我们的比对器产出的 SAM 直接就能进这条链：`Mapper` 比对 → `write_mapped_sam(...)` 落盘 →
`iter_pileup(reference, path)`。

错误率表是"扫一遍堆叠数出来的"，同样既吃文件也吃记录：

```python
from modules.bio_analysis_function.submodules.consensus_calling import build_error_rates

rates = build_error_rates(reference, "mapped.sam")

rates.summary()
# {'observations': ..., 'rows': ..., 'skipped_reference_ambiguous': ...,
#  'skipped_read_ambiguous': ..., 'skipped_long_deletions': ...}

# 某个碱基在某质量下的经验错误率：把 r 读成 C 的概率
rates.probability("A", "C", 40)      # P(观测到 C | 参考是 A, 质量 40)
rates.match_probability("A", 40)     # P(观测到 A | 参考是 A, 质量 40)
rates.row("A", 40)                   # 该行的完整分布（A/C/G/T/- 五项，和为 1）
rates.rows()                         # 已观测到的 (参考碱基, 质量) 行
```

判定就是拿这张表逐位置打分，产出报出来的碱基替换（按参考名、位置升序）：

```python
from modules.bio_analysis_function.submodules.consensus_calling import (
    ConsensusSettings,
    call_consensus,
    score_position,
)

# 不给 rates 就用同一份数据自己建表（会在数据上多扫一遍；文件输入没问题）
for call in call_consensus(reference, "mapped.sam"):
    print(call.seq_id, call.position, f"{call.reference_base}→{call.call_base}",
          call.consensus_score, call.frequency, call.total_reads)

# 阈值可调：默认就是上游的 E-value 10 / 频率 0.8
calls = list(call_consensus(reference, records, settings=ConsensusSettings(e_value_cutoff=20.0)))

# 想看不报的位置也打了多少分（调试、对拍、出报告）
column = next(iter(iter_pileup(reference, "mapped.sam")))
score = score_position(column, rates)
if score is not None:
    print(score.position, score.best_base, score.ratios)   # ratios: 四个候选的似然比
```

多态档换的是模型（混合模型，见第 4 节第 11 条），所以是另一组入口：

```python
from modules.bio_analysis_function.submodules.consensus_calling import (
    PolymorphismSettings,
    call_polymorphisms,
    call_variants,
    score_polymorphisms,
)

# 只跑多态档（默认 0.05 ≤ f̂ < 0.8、打分 ≥ 3）
for call in call_polymorphisms(
    reference, "mapped.sam", settings=PolymorphismSettings(min_frequency=0.1)
):
    print(call.seq_id, call.position, f"{call.reference_base}→{call.call_base}",
          call.frequency, call.score, call.variant_reads, call.total_reads)

# 两档一次跑出，按位置排序；polymorphism=None 表示只要共识档
variants = list(call_variants(reference, "mapped.sam"))
consensus_only = list(call_variants(reference, "mapped.sam", polymorphism=None))

# 某个位置每个候选碱基的混合模型打分（f̂ 与似然比）
for item in score_polymorphisms(column, rates):
    print(item.call_base, item.frequency, item.likelihood_ratio)
```

## 3. 参数

| 参数 | 默认 | 含义与取舍 |
| --- | --- | --- |
| `default_quality` | 0 | `QUAL` 为 `*`（没有质量）时使用的质量。默认 0 是**保守**选择：把未知质量当最差，而不是假装它很好。若上游工具导出的 SAM 缺质量，应显式指定一个合理的值 |
| 伪计数 | 固定 1 | **不做成参数**：上游就是 1。要改这个值需要数据支撑（比如拿一组已知突变评估"多少伪计数最稳"），那是调参实验的结论，不是配置项能解决的问题 |
| `e_value_cutoff` | 10 | 共识打分下限。**越大越显著**（它是负对数尺度上的量，不是通常"越小越好"的 E 值）；调大更严、漏检更多，调小假阳性更多 |
| `frequency_cutoff` | 0.8 | 支持判定碱基的观测占比下限。consensus 模式假定变异在样本里占 100%，0.8 是给"少数 read 恰好带错误/来自污染的拷贝"留的余量 |
| `min_frequency`（多态档） | 0.05 | 混合比例 `f̂` 的下限，低于它视为噪声不报。**这个默认值是我们的取值，不是上游的**（见第 4 节第 11 条）；上游靠统计检验筛，我们靠这个门槛 |
| `max_frequency`（多态档） | 0.8 | 混合比例 `f̂` 的**上限（不含）**：达到它的位置归共识档，本档不重复报。**建议与 `ConsensusSettings.frequency_cutoff` 设成同一个值**，否则两档之间会出现一小段没人管、或两边都管的频率区间 |
| `e_value_cutoff`（多态档） | 3.0 | 多态打分 `ratio − log₁₀(参考总长)` 的下限。比共识档的 10 松——多态本身就是"少数派"，观测本来就少、似然比天然更小。同样是**我们的取值** |
| `rates` | `None` | 预建的错误率表。不传就用同一份数据自训练（多扫一遍）；**建表与判定用不同数据**时显式传入 |
| `trimming` | `None` | read 端裁剪表（`build_trimming` 的产物）。给了它，被裁的末端碱基既不进错误率表、也不参与似然。**默认不裁剪**——上游默认是裁的，但这里不替调用方做决定（要裁剪就显式传，见第 4 节第 10 条） |

## 4. 十二条必须知道的约定

1. **输入是 SAM，不是比对器的内部对象**。这样本模块只依赖 `common/`，不依赖
   `submodules/read_mapping/`（开发规则 3.1 第 4 条）；同时换一个比对器（bowtie2）产出的
   SAM 也照样能进这条链——这正是算法清单 5.5.3 里"接受外部 SAM/BAM"想要的入口。
2. **`SEQ` 是与参考同向的**（SAM 规范），所以负链记录**不需要**再翻转；`is_reverse` 只用来
   统计"这条证据来自哪条链"。
3. **位置是 0-based**（SAM 的 `POS` 是 1-based，读进来时换算）；`read_offset` 是该碱基在
   `SEQ` 里的下标、`read_length` 是 `SEQ` 长度——read 端裁剪（分片 D）靠这两个字段判断
   "这个碱基离 read 末端还有多远"。
4. **插入挂在它前面那个参考位置上**，缺失落在它覆盖的**每一个**参考位置上；软剪裁不产生
   任何证据；`N` 跳过的区域不承载证据，也不做插入挂靠（紧随其后的插入不记录）。
5. **质量是 SAM 的 Phred+33 解出来的整数**；`*` 一律用 `default_quality`。缺失本身没有质量，
   按上游的约定用"read 中紧随其后的那个碱基的质量"代表它。
6. **只有单碱基缺失进错误率表**（作为 read 类别 `-`）。更长的缺失属于 junction 那一路的证据，
   单独计数上报（`skipped_long_deletions`），不能混进"单碱基错误率"里。
7. **非 ACGT 不参与统计**：参考碱基是 `N` 的位置、read 碱基是 `N` 的观测都被排除，并分别计数
   上报。**没有任何观测的 (参考碱基, 质量) 行返回均匀分布**（五个类别各 1/5）——等于说
   "这个质量上数据什么都没告诉我"，比编造一个错误率诚实，方向上也让判定更保守。
8. **判定用的是似然比，不是绝对似然**：`ratio(X) = Σᵢ[log₁₀P(bᵢ|X,qᵢ) − log₁₀P(bᵢ|R,qᵢ)]`
   （即 `log₁₀(L(X)/L(R))`，`ratio(R) = 0`），**共识打分 = `ratio(X*) − log₁₀(参考总长)`**。
   减参考总长是把"全基因组每个位置都试过一遍"的多重比较折进去。**并列时保留参考碱基、不报**
   （典型情形：错误率表退化成均匀分布，四个候选比值全是 0）——证据不足就留在"没变化"那侧。
9. **这一片只判碱基替换**。插入/缺失证据（`I`/`D`）**不参与**判定：缺失要和重复序列背景一起
   看（分片 D 的 read 端裁剪），塞进同一个似然里会让"频率按什么算"变含糊。小 indel 的判定
   留给后续分片，所以现在产出的是上游 `SNP/SUB` 那一类。
10. **read 端裁剪是显式的一层，默认不开**。参考里 1–18 bp 的完全重复会让 read **末端**那几位
    碱基"多解"：它们既支持"序列没变"、也支持"重复拷贝数变了"。`build_trimming` 算出每个位置
    两端各要裁几个（**每端至少 1**），把结果传给 `iter_pileup` / `build_error_rates` /
    `call_consensus`，被裁的碱基就会被打上 `trimmed` 标记、不参与错误率与似然（但仍然记录在
    堆叠里，便于解释"这里覆盖度为什么低"）。**不传 `trimming` 就是不裁剪**——上游默认裁，
    但这是会影响结果的决定，本模块不替调用方默认打开。
11. **多态档必须换模型**。上游 `prediction=polymorphism` 报的往往是**少数派**碱基——真实产物
    里频率低到 7%–12%（如 `RA 37 … 0 C T frequency=1.04031563e-01`：参考 C 仍是多数派，T
    只占一成）。用共识档那套"最佳碱基与参考不同"永远看不到它，因为**少数派的似然必然低于
    参考**。所以多态档改用**混合模型**：假设群体里比例 `f` 的个体在 `X` 上变了、其余仍是参考
    `R`，单条观测概率是 `f·P(b|X,q) + (1−f)·P(b|R,q)`；对每个候选 `X ≠ R` 在 `f` 网格
    （0.01 步长、上限 `f < max_frequency`）上取最大似然得 `f̂`，比值对的是**纯参考解释**
    `L(f=0)`（"看到的差异全是测序错误"）：`ratio = log₁₀[L(f̂)/L(f=0)]`，
    `score = ratio − log₁₀(参考总长)`。两档的 `score` 同名同尺度（都减了参考总长），但分子
    模型不同，**不能直接比大小**。
12. **两档按 `f̂` 互斥，同一个位置只报一次**。`f̂ ≥ max_frequency` 归共识档、
    `[min_frequency, max_frequency)` 归多态档、`< min_frequency` 不报。`call_polymorphisms`
    会先跑一次 `score_position` 做归属检查：位置若已被共识档认领（最佳碱基≠参考且频率
    ≥ `max_frequency`）就整个跳过，避免一个位置两档都报。**默认阈值（0.05 / 0.8 / 3.0）是
    我们的取值**：上游多态档还带统计检验与链偏好检验（证据行的 `bias_p_value` /
    `fisher_strand_p_value`），我们没有复刻——没有那套检验，就把门槛显式留成参数，真实数据上
    按需要调，而不是假装有统计显著性。两个上限建议与共识档的 `frequency_cutoff` 取同一个值。

## 5. 怎么跑测试

```bash
python -m pytest modules/bio_analysis_function/submodules/consensus_calling -q
```

**63 项**全过（堆叠 **17** + 错误率重校准 **11** + 共识打分与判定 **10** + 端裁剪与端到端 **13**
+ 多态档 **12**）。
用例全部**手写 SAM 记录**、期望值能手算，不调用比对器——输入契约就是公共层的 SAM，
测试只依赖那一层。

- **堆叠**覆盖：`M` 产生逐位观测（碱基、质量、MAPQ、链向、read 内下标）、软剪裁推进下标但不产
  证据、插入的挂靠位置与质量、缺失落在每个被覆盖位置且带"下一个碱基"的质量、`N` 跳过区不产证据、
  紧随 `N` 的插入不记录、末尾插入挂到最后位置、开头插入无锚点不记录、负链不翻转、覆盖度与链计数、
  质量缺失用默认值、`N` 碱基被标记但不丢弃、未比对与无序列记录被跳过、只按位置升序输出有证据的列、
  参考名不存在报错、从 SAM 文件与从记录序列结果一致。
- **错误率重校准**覆盖：伪计数与归一化（期望概率能手算，如 4 个匹配 → `P(A|A,40)=5/9`）、
  错配把行往错配碱基拉、不同质量分成独立行互不影响、**质量越低经验错误率越高**（单调性）、
  单碱基缺失进入 `-` 类别且质量取"紧随其后的碱基"、**长缺失只计数不入表**、参考/读段非 ACGT 的
  排除与计数、未观测行回退成均匀分布、非法查询报错、从 SAM 文件构建与从记录构建结果一致。
- **共识打分与判定**覆盖：似然比与共识打分的**解析值**（8 条支持 T、2 条支持参考 C 时正好是
  `6·log₁₀(250)`，减去 `log₁₀(1000)`）、`score_position` 给出四个候选且参考碱基恒为 0、
  频率阈值与 E-value 阈值**各自独立生效**（改一个不影响另一个）、完全匹配的数据一条不报、
  空表（全均匀 → 全并列）一条不报（同时证明 `rates` 参数确实被用上）、参考碱基是 `N` 或只有
  `N` 观测时返回 `None`、多个调用按位置升序、**生成器输入被先定住**（两遍扫描不漏数据）、
  以及一条**已知现象**：小样本自训练时弱变异会被自己抬高的错误率压住（真实数据变异占比 <1‰
  时可忽略，用测试钉住免得被当成 bug 去改）。
- **read 端裁剪与端到端**覆盖：同聚物/双碱基周期重复的裁剪数逐位手算（`TTAAAAGGG`、
  `TTAGAGAGCC`）、重复区外的位置只剩"每端至少 1"、单拷贝不算重复、`max_unit` 能挡住更长的
  周期、越界位置报错、每条序列一张表；堆叠里**只有 read 两端**被打上 `trimmed`（中间的碱基
  照常可用）、不给裁剪表就一个都不标、缺失证据也带标记；被裁的观测**不进错误率表**（观测数
  与 `skipped_trimmed` 对得上）、以及一条行为用例——末端落在重复里的噪声 read 会把频率压到
  阈值之下、裁掉之后真变异才浮出来（不裁不报、裁剪报出，频率 1.0、总观测 6 条）；
  最后是**端到端对拍**：3 个已知替换、每个 20 条支持 read，检出集合与真值集合逐项吻合
  （精确率与召回率都是 1，频率 20/21、打分 ≥ 10）。
- **多态档**覆盖：能报出少数派（8T+12A 报 T、打分 ≈ 6.7）、只有 1 条少数派时不报、
  3/60 的弱证据不报（阈值挡住）、全 `N` 位置跳过、同一位置两个候选碱基各自打分；
  **两档分工**——共识档对少数派位置完全静默、18/20 的高频位置归共识档、`f̂=0.8` 边界归
  共识档（曾经差点两档都报，用测试钉住）；三个阈值（`min_frequency` / `max_frequency` /
  `e_value_cutoff`）各自独立生效；`call_variants` 两档合并后按位置升序、`polymorphism=None`
  只要共识档。

## 附：设计记录

### 上游是什么（带出处）

breseq 的 `RA` 证据线做三件事，出处：[breseq 0.35.7 文档 · Methods](https://gensoft.pasteur.fr/docs/breseq/0.35.7/methods.html)
（`https://gensoft.pasteur.fr/docs/breseq/0.35.7/methods.html`）：

1. **read 端裁剪**：先在参考里找 1–18 bp 的**完全重复**，据此决定"从 read 末端起要裁掉几个
   碱基才能让剩下的比对对'重复拷贝数变化'这件事不再模糊"。**每端至少裁 1 个碱基**——因为
   单个碱基到底是原来那个还是新插入的拷贝，永远无法只凭这条 read 判断。文档给的例子很直白：
   没有裁剪时，跨过重复区两侧、但没跨过整段重复的 read 会被当成"这里没变化"的**反证**，
   从而把真的插入/缺失压下去。**这条归分片 D。**
2. **碱基质量重校准**：不直接信 FASTQ 的质量值，而是**用数据自己数**——统计"参考碱基 ×
   read 碱基"的出现次数并按 read 碱基的质量分箱（单碱基缺失用一种特殊的"碱基"进入统计，
   用 read 中下一个被比对碱基的质量），**每个格子加伪计数 1**，再用"该 (参考碱基, 质量) 一
   行里各 read 碱基的总计数"把计数除成频率。前提假设是"绝大多数的读段—参考不一致是测序错误，
   而不是真实变异"——对差异 <1‰ 的目标数据成立（`AlgorithmSettings` 的 5.5.1 也写了这条前提）。
   **这条归分片 B。**
3. **共识打分**：每个位置对四种碱基各算一个似然 `L`，取最大的那个；若它不是参考碱基，
   就用 **`log₁₀L − log₁₀(所有参考序列的累计长度)`** 作为该预测的"consensus E-value"
   打分（减参考总长是把"全基因组那么多位置都试过一遍"的多重比较折进去）。默认判定阈值：
   **E-value 打分 ≥ 10 且频率 ≥ 0.8**（参照 breseq 运行摘要里的 `Consensus mutation E-value
   cutoff = 10`、`Consensus frequency cutoff = 0.8`）。**这条归分片 C。**

上游还有 consensus（默认，纯克隆群体）与 polymorphism（`-p`，混合群体）两种模式。**多态档
（分片 E）的做法与依据**：上游的 `RA` 证据行用 `prediction=polymorphism` 标记多态，真实产物里
这类调用的频率常常很低（一个典型行是 `RA 37 … 0 C T frequency=1.04031563e-01`——参考 C 仍是
多数派、T 只占约一成），而证据行还带 `bias_p_value`、`fisher_strand_p_value` 这类统计检验字段。
我们的方法是：**不沿用共识档的判据**（少数派似然永远低于参考），改用上面第 11 条那套**混合模型
最大似然 + 纯参考解释做对照**，`score = ratio − log₁₀(参考总长)` 与共识档同一折减口径，
阈值显式留成参数。**统计检验没有复刻**——这是我们与上游的已知差异，写进「已知限制」。

### 为什么先做堆叠、且从 SAM 进

共识调用、多态性调用（后续）、以及 MC 覆盖度分析都要"逐位点看 read"，所以堆叠是这条线的地基。
按开发规则 3.2，"只是某个算法内部的一步"的能力本可以放公共层，但**公共能力要等到至少两个
真实使用方出现才提取**（项目约定）——现在只有共识调用一个使用方，因此先放在本模块内；
等多态性调用/MC 真的要用时再提到 `common/`，那时接口也已经被两处用出形状了。

从 SAM 进而不是从 `read_mapping` 的 `Alignment` 进，理由见第 4 节第 1 条：一是**边界**
（子模块之间不互相依赖），二是**宽度**（外部比对结果也能进）。

### 已定的实现取舍

- **只输出有证据的位置**：整条参考逐位输出在细菌基因组上是 3–5 百万个空列，白费内存与时间；
  下游（打分、覆盖度）也只关心有 read 的地方。
- **缺失的质量取"紧随其后的碱基"**：缺失没有自己的质量，上游用下一个被比对碱基的质量，
  本实现沿用——这样单碱基缺失在重校准表里也能按质量分箱，而不是笼统地算成一类。
- **`N` 一类非 ACGT 碱基照实记录、但标记 `is_ambiguous`**：堆叠层不做"要不要用"的决定，
  把判断留给重校准与打分（它们会排除这些观测）。静默丢弃会让"某位置覆盖度为什么低"变得
  无法解释。
- **已比对却没有 CIGAR 的记录直接跳过**：没有 CIGAR 就没有位置对应关系，猜一个位置比不猜更糟。
- **插入无锚点时不记录**（比对以插入开头、或插入紧跟在 `N` 之后）：堆叠是按参考位置组织的，
  这种插入没有可表达的坐标；将来做 junction 证据时它们由另一条路径处理（分片 B 之外的事）。

**分片 B（错误率重校准）另加的取舍：**

- **长缺失不进表，只计数**（`skipped_long_deletions`）：上游在预处理里就把 >2 bp 的 indel 拆成
  子比对，`RA` 线只管小 indel；把长缺失算进"单碱基错误率"会让这张表失去意义。
- **非 ACGT 分别计数排除**（参考碱基是 `N` / read 碱基是 `N` 两类）：这是"表看起来不对"时最
  常见的两个原因，必须能解释，所以分开上报而不是合并成一个"跳过数"。
- **未观测的行回退成均匀分布**：低覆盖时某些 (参考碱基, 质量) 组合可能一条都没有。这时
  "每类各 1/5"等于承认信息不足；若强行给一个错误率，会让打分凭空自信。
- **质量不合并**：每个整数质量一个行。这是"不引入无依据的调参"的选择——上游也只说按质量分箱；
  真到了低覆盖数据上发现行太稀，再拿数据决定怎么合并（记进待办），而不是先加一个开关。

**分片 C（打分与判定）另加的取舍：**

- **算似然比而不是绝对似然**：绝对似然是连乘出来的极小正数，读起来毫无意义；比值直接回答
  "这个碱基比参考好多少"。实现里把参考碱基那一项减掉，于是 `ratio(R) ≡ 0` 成了免费的自检。
- **并列时保留参考碱基**：报突变是要付代价的结论。典型触发场景是错误率表退化成均匀分布
  （该质量没观测）——这时四个候选的比值全是 0，按"取最大"的朴素写法会随手报成 A/C/G/T 里
  排前面的那个，那是真 bug；严格大于才替换就自然避开了。
- **`log₁₀` 每列只算"不同组合"次**：一列里同一个 (候选, 观测碱基, 质量) 会反复出现，加一层
  小缓存把取对数次数从 `观测数 × 4` 降到"不同组合数"，代码只多三行。
- **只判碱基替换**：`I`/`D` 不参与（理由见第 4 节第 9 条）。这条取舍换来的是"频率"含义明确：
  分子分母都是**该位置的碱基观测**，不含缺失、不含 `N`。
- **两遍扫描时把迭代器定住**：`rates` 不给就要先建表再判定。文件输入重新打开即可；迭代器若不
  先转成元组，第二遍读到空——这条有测试盯着（不然是个静默的"什么都不报"）。

**分片 D（read 端裁剪）另加的取舍：**

- **裁剪数是对上游定性描述的重建**：上游只说"找 1–18 bp 的完全重复、算每端要裁几个、
  每端至少 1 个"，没给算法。本实现把它写死成"以覆盖该位置的最长合法重复区间为准：
  左端裁到区间右端、右端裁到区间左端"，并要求**至少两个完整拷贝**才认——否则一次偶然相同的
  碱基就能凭空造出裁剪。**不承诺与上游逐位一致**，与"比突变集合"的验收口径一致。
- **懒计算 + 缓存，不预建整表**：给整条细菌基因组 × 18 个周期预扫是几千万次比较；而真正用到
  的只有"每条 read 首尾落在哪儿"，按位置算、算过缓存即可（同一批数据里首尾位置高度重复）。
- **被裁的碱基仍然记录、只打标记**：静默丢弃会让"这里覆盖度为什么低"无法解释——与 `N` 碱基、
  长缺失的处理保持同一套立场（记下来 + 单独计数/标记）。
- **裁剪是显式开关，默认不开**：它会改变结论，所以不替调用方默认打开。代价是"忘了传就少了
  一层保护"，但这条写进了参数表、约定与本文档。
- **插入证据不带裁剪标记**：目前没有任何判定消费插入，加一个没人看的字段只是噪声；
  将来做小 indel 判定时再补（已经写在 `pileup.py` 的类型注释里）。

**分片 E（多态档）另加的取舍：**

- **不沿用共识档，另起一个类型**：`PolymorphismCall` 独立于 `ConsensusCall`（两者都有
  `prediction` 字段，下游可统一按它分派）。硬把两档塞进一个类型会让人误以为"字段相同、含义
  相同"，而 `score` 的分子模型其实不同（第 11 条）。
- **比值对的是"纯参考解释"而不是参考碱基的似然**：共识档的 `ratio` 是 `log₁₀(L(X)/L(R))`，
  多态档若照抄，`f` 很小、`L` 又必须在参考点取，噪声会主导。改用 `L(f̂)/L(f=0)` 后，
  "这个位置有没有别的碱基"直接回答问题本身，且 `f̂=0`（纯参考最好）天然等于"不报"。
- **`f` 用 0.01 步长的网格，不上连续优化**：报告里频率的精度没有意义，网格够用且结果确定
  （不引入优化器的收敛差异）；`f=0` 单独算，因为它是参照点、不属于搜索范围。
- **一列里每个候选各判一次**：一个位置理论上可能有两个少数派（极少见），都过阈值就都报，
  排序按打分降序、再按碱基名，保证输出确定。
- **归属检查放在多态档里、而不是共识档**：多态档多跑一次 `score_position` 判"这个位置是不是
  已经归共识档"，共识档因此完全不必知道多态档存在。代价是多扫一遍打分，换来两档解耦。
- **阈值默认值明确标注为"我们的取值"**：上游靠 `bias_p_value` 一类统计检验筛多态，我们没复刻；
  与其编一个看似有依据的数字，不如把三个门槛留成参数并在文档里写清来源（这条比数值本身重要）。

用例的设计原则是"期望值能手算"：参考取 32 bp（或 1000 bp 的 `ACGT` 重复、固定种子的随机序列）
已知序列，SAM 记录手写，逐项核对坐标、碱基、质量、链向、`read_offset`，以及插入/缺失的挂靠
位置。**没有**调用比对器——这条测试同时证明了"输入契约只到公共层 SAM 为止"。

打分那组刻意把**建表**与**判定**分成两份数据（训练：一条 996M 完全匹配 read；判定：只覆盖某
位置的一批短 read），于是期望值可以写成解析式：每个 (碱基, 质量 40) 行恰好 249 个匹配观测，
`P(X|X,40) = 250/254`、`P(其它|X,40) = 1/254`，8 条支持 T + 2 条支持参考 C 时比值正好是
`6·log₁₀(250) ≈ 14.388`、共识打分 `≈ 11.388`（阈值 10，报出）、频率正好 0.8（阈值 0.8，报出）。
两个阈值各自还有"只改一个"的用例，避免它们互相掩盖。

多态档沿用同一套"期望值能手算"的办法，但**判定位置放在训练覆盖之外**：训练 read 只覆盖 0-based
0–299，判定位置取 320 / 356（参考碱基都是 A）。原因是第一版测试把判定数据也拿去建表，自训练
抬高了错误率，结果一条都报不出来——这与共识档那条"小样本自训练吞噬弱变异"是同一个效应，
只是多态档的弱证据更容易被它压死。**教训**：测试里建表与判定必须分家，否则验的是模型的自洽性
而不是模型本身。

**写 D 的时候被测试抓到一个真 bug**：`_compute_extent` 向左扩时只判了 `start - unit >= 0`，
没判右半边是否还在序列里——位置靠近末端、`unit` 又大时会直接 `IndexError`（`TTAAAAGGG` 的
第 5 位、`unit=8` 就能触发）。补上边界后消失。另一处是**测试自己的错**：我原以为
`TTAGAGAGCC` 位置 8 不属于任何重复，实际尾部 `CC` 就是一个周期 1 的两拷贝重复——代码是对的，
改的是断言。

### 已知限制与待办

- **只判碱基替换，indel 未判**：`I`/`D` 证据这一片不参与判定，所以现在还报不出小插入/缺失
  （上游 `RA` 能报 ≤2 bp 的 indel），更别说 `JC` 那一路的结构变异——那本来就在 v1 范围外
  （算法清单 5.5.3 第 2 条）。
- **小样本自训练会吞噬弱变异**：错误率表是从同一份数据数出来的，变异自己会抬高
  "把参考碱基读成变异碱基"的经验错误率。变异占比越低（真实数据 <1‰）影响越小；但当样本里
  某个位置明显偏离、整体观测又少时，这个效应是真的。有测试钉住这一现象，免得被当成 bug。
- **多态档没有复刻上游的统计检验**：上游的 `prediction=polymorphism` 证据行带
  `bias_p_value`、`fisher_strand_p_value` 等字段（链偏好 / 群体检验），本实现只做了混合模型的
  最大似然比 + 三个可调门槛，**没有**这些 p 值。因此我们报出的多态不能直接与上游的
  "polymorphism" 逐条对等比较——频率与打分给出的是"这里有没有别的碱基、占多少"的估计，
  不是显著性水平。上游的默认阈值一律没抄（0.05 / 0.8 / 3.0 都是我们的取值）。
- **两档的 `score` 不可直接互比**：虽然同名同尺度（都减了 `log₁₀(参考总长)`），共识档的分子是
  `L(X)/L(R)`、多态档是 `L(f̂)/L(f=0)`，模型不同。跨档比较请只看 `frequency` 与 `prediction`。
- **没有链偏好/最低覆盖过滤**：上游有 `--consensus-minimum-*` 一串过滤（默认**关**），本实现
  一条也没做——先把打分做对，过滤等有真实数据再谈（记进待办）。判定的证据里其实已经带了
  `mapq` 与链方向，加过滤是小的增量。
- **裁剪规则不承诺与上游一致**：见上面的取舍；真要做阶段级对拍时，这一层差异会体现在"哪些
  位置有证据"上，属于允许的差异（验收比突变集合）。
- **只适合小规模**：本实现把每个位置的观测收进内存再排序输出。细菌基因组 100× 覆盖在
  Python 里是几百 MB 到 GB 量级，真实数据必须换成流式（按参考位置顺序边读边聚）或原生实现。
  这也是"为什么最终要进原生层"的又一条理由（前一条在 `read_mapping.md` 的实测里）。
- **质量不合并，低覆盖时行会很稀**：某个 (参考碱基, 质量) 行若只有伪计数，概率就退化成均匀
  分布（等价于"这个质量什么都没告诉我们"）——方向上保守，但会让证据被系统性削弱。真实数据上
  要不要按相邻质量合并，需要拿数据评估后再定（现在不预设开关）。
- **不做多重命中的取舍**：观测里带了 `mapq`，但堆叠层**不筛**——上游把比对分成
  unique / repeat 两类，并在部分计算里只看 unique-only 位置；这件事留给分片 C/后续，
  因为"要不要排除"是打分模型的决定，不是堆叠的决定。
- **线性空位、无相邻碱基上下文**：错误率只按"参考碱基 × read 碱基 × 质量"分箱，没有把
  "相邻碱基是什么"（上游提到的 covariate 之一）和读段位置纳入模型。上游也只做到质量这一维，
  所以先跟上，不做超出上游的复杂度。
- **同类序列（环状参考原点跨越）不处理**：与 `read_mapping` 同一条限制，read 必须完整落在
  参考范围内。
- **算法广场入口已登记契约**（`bio-consensus-calling`，分类「变异检测」，`status: beta`，
  输入字段按数据流角色标注：参考基因组是 `resource`、SAM 是 `upstream`、输出 TSV 是 `output`），
  但**执行链路未接通**——界面会照实提示"只登记调用契约，提交会被拒绝"。要接通还需两步：
  给本模块加一个 JSON 入口（照 `modules/workflow` 的 `wrapper.py` 那样收 JSON、吐 JSON），
  再把方法 id 加进 `LOCALLY_EXECUTABLE_METHOD_IDS`；这两步属于后续任务。
- **与上游的对照尚未做**：分片 D 的端到端对拍用的是**自己合成**的已知突变数据集
  （检出集合与真值集合吻合）；真正的阶段级对拍要拿一份外部比对结果（bowtie2 写的 SAM）
  喂进来、与 breseq 的突变集合比，这需要能装上游工具的环境。
