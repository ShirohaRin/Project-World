# PPT 笔记归档器

## 目标

把 PowerPoint 作为原始资料，整理成一个或多个适合知识库长期维护的 Markdown 笔记。正文按知识主题组织，而不是逐页抄录；课件中的定义、术语、公式、例题、表格、结论和习题等主要文字必须完整保留。新增知识必须与课件内容明确区分。

## 输入与输出

输入可能包括：

- 一个或多个 `.ppt`、`.pptx` 文件；
- 目标知识库根目录；
- 用户指定的分类、输出目录、文件名、标签或扩充范围；
- 可选的课件转写文本、讲义或参考资料。

输出通常包括：

- 一个或多个主题化 `.md` 笔记；
- 必要时的图片、结构式或图表素材及 Markdown 链接；
- 逐页原始文本中间文件，用于核对；
- 简短的归档核验结果和待人工确认项。

未经用户要求，不删除或覆盖原始 PPT，不额外创建 README、说明书等文件。

## 工作流程

### 1. 确认范围

先定位实际 PPT，确认文件格式、页数、目标知识库和输出位置。读取目标知识库现有目录与相关笔记，避免重复建档。若章节归属、输出拆分方式或图片处理方式不明确，优先询问；可以合理判断时直接执行并在结果中说明假设。

### 2. 提取原始内容

- `.pptx` 优先使用可读取文本框、表格、备注和图片信息的解析方式；
- `.ppt` 是旧式二进制格式，普通文本读取不可用时，使用本机 PowerPoint COM 或可用转换工具；
- 按页保存原始文字，保留页码分隔，作为后续覆盖核对依据；
- 同时记录标题、正文、列表、表格、备注、图片和公式等元素；
- 提取失败或 PowerPoint 不可用时，不假装完成，说明失败位置并采用可行替代方案。

### 3. 分析主题与规划文档

根据实际内容识别课程、章节、主题和概念关系，再决定生成一个还是多个笔记。按主题拆分，例如“课程绪论”“蛋白质”“氨基酸性质”，不要机械按幻灯片拆文件。章节信息优先写入 front matter 的 `tags`，不要把“第几章第几节”强行写入正文标题，也不要无意义地增加“本节目录”。

规划时检查：

- 同一概念是否被多页重复解释；
- 定义、分类、性质、机制、例题之间的关系；
- 表格、公式和口诀是否适合转换为 Markdown 表格；
- 是否存在课件原文与教材常识不一致的地方。

### 4. 按统一格式写笔记

默认使用以下结构，可按主题调整：

```markdown
---
tags:
  - 领域
  - 子领域
  - 课程笔记
  - 章节标签
来源: "原始文件名.pptx"
---

# 主题名称

## 核心概念

## 结构、分类或组成

## 性质、机制与过程

## 例题、公式或应用

## 课件习题

## 补充知识

> **补充：** 这里的内容不是原始课件文字，是为理解、联系或校正而增加的知识。
```

规则：

- 正文用自己的统一笔记语言重组，不逐页复制；
- 课件中的全部关键文字要融入对应主题；不能因改写而丢失限定条件、数字、公式、例题、习题或列表项；
- 课件原文与补充知识分开，不能把推断、外部资料或模型生成内容伪装成 PPT 原文；
- 公式、专有名词和数值尽量保持原样；版式变化不能改变含义；
- 口诀、对照关系、分类项目、实验条件等优先使用 Markdown 表格；
- 课件中可能存在错误时，保留其原始表述，并在补充区域写出“校订说明”，不得无提示地改写原文；
- 不为每一页创建同名小节，除非用户明确要求逐页记录。

### 5. 处理图片和特殊元素

发现结构式、示意图、曲线、流程图、扫描文字或表格时，先判断它是否承载不可替代的信息：

- 可转写的信息，转为正文、公式或表格；
- 不能可靠转写的内容，提取图片或保留原页截图，并使用相对路径链接；
- 不凭空补画化学结构、实验结果或图中数值；
- 图片来源、页码和无法确认的内容记录在核验结果中。

### 6. 专业扩充

只补充有助于理解课件内容的必要知识，例如术语解释、前置概念、公式含义、常见应用、概念之间的联系或可靠的校订。扩充不能喧宾夺主，也不能把尚未验证的推测写成确定事实。需要外部资料时记录来源；用户只要求整理课件时，不自行扩大研究范围。

### 7. 核验

完成后必须进行以下检查：

- 输出目录和所有 Markdown 文件确实存在；
- front matter 可解析，来源文件名正确，标签与实际章节一致；
- 原始逐页文本与最终笔记逐项比对；定义、术语、公式、数字、表格、例题、结论和习题无明显遗漏；
- 补充内容均有明确标记；
- 内部链接、图片链接和表格语法有效；
- 没有把页码、解析噪声或重复内容大量带入正文；
- 无法确认的章节、文字或图像信息列入“待人工确认”，不擅自猜测。

## 交付说明

向用户报告：处理了哪些文件、生成了哪些笔记、原始内容是否完成覆盖、补充内容放在哪里、哪些图片或公式未能可靠转换，以及仍需人工确认的问题。只陈述实际执行过的操作，不声称未验证的覆盖率或事实准确性。

## 何时使用脚本和参考资料

只有在同类任务反复出现或需要确定性检查时，才为本 Skill 添加 `scripts/`，例如逐页提取、原文覆盖率比对或 front matter 校验。格式规范、具体知识领域和大型示例应放入 `references/`，不要把大量领域知识堆进本文件。没有实际用途的初始化示例文件应删除。
