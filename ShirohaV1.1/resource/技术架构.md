## 2. 技术选型

### 2.1 前端技术栈

| 技术 | 版本 | 用途 |
|------|------|------|
| Vue | 3.x | 前端框架（Composition API） |
| Vite | 5.x | 构建工具 / 开发服务器 |
| TypeScript | 5.x | 类型安全 |
| CSS Variables | - | 设计系统 / 主题 |
| CSS Animation / Transition | - | 动画效果 |

### 2.2 为什么不用这些？

| 技术 | 不使用原因 |
|------|-----------|
| Tailwind CSS | 项目有独特的视觉风格，自定义 CSS 更灵活 |
| Pinia | 项目规模小，Vue 响应式 API 足够 |
| Vue Router | 单页应用，无路由需求 |
| UI 组件库 | 所有组件高度定制，通用组件库不适用 |

### 4.1 资源加载模块 (useLoading)

**职责**：预加载所有静态资源，计算真实进度

```typescript
interface LoadingResource {
  url: string;
  type: 'image' | 'audio';
  weight: number;  // 权重，影响进度占比
}

function useLoading(resources: LoadingResource[]) {
  const progress = ref(0);
  const status = ref('initializing');
  const isComplete = ref(false);
  
  // 分阶段加载
  // 阶段1：图片资源（权重 60%）
  // 阶段2：音频资源（权重 40%）
  
  return { progress, status, isComplete };
}
```

## 5. 状态管理策略

由于项目规模较小，不引入 Pinia，采用以下策略：

1. **全局状态**：通过 `provide/inject` + 组合式函数共享
   - BGM 播放状态（全局唯一）
   - 用户名（登录后全局可用）

2. **组件状态**：组件内部 `ref` / `reactive` 管理

3. **派生状态**：`computed` 计算属性

## 6. 性能优化策略

| 优化点 | 方案 |
|--------|------|
| 图片加载 | 预加载 + 懒加载，WebP 格式 |
| 音频加载 | 按需加载，不预加载全部 |
| 动画性能 | 优先使用 transform / opacity 属性，开启 GPU 加速 |
| 粒子优化 | 限制粒子数量（30 个），使用 CSS 动画而非 JS |
| 重绘优化 | 减少布局抖动，使用 `will-change` |

## 9. 游戏模块设计（占位）

小游戏采用**独立 JS 文件**的方式管理：

```
src/games/
├── index.ts            # 游戏注册表
├── snake/              # 贪吃蛇游戏
│   └── game.js
├── tetris/             # 俄罗斯方块
│   └── game.js
└── ...
```

每个游戏导出统一的接口：
```javascript
export default {
  name: '贪吃蛇',
  description: '经典像素贪吃蛇',
  thumbnail: '...',
  init(container) { /* 初始化游戏 */ },
  destroy() { /* 清理资源 */ }
}
```
