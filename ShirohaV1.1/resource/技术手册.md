# Shiroha 领域 · 技术手册

## 📋 项目概述

**项目名称**：原野 · Shiroha领域  
**项目类型**：单页个人网站 / 互动主页  
**技术栈**：原生 HTML5 + CSS3 + JavaScript（无框架依赖）  
**入口文件**：`3.html`

这是一个具有高度视觉表现力的个人主页，采用毛玻璃拟态设计风格，融合了动态背景、粒子效果、动画过渡、实时天气等多种交互元素。

## ⚡ 核心功能模块

### 1. 加载进度系统

**文件位置**：`3.html` 第 86-161 行（CSS），第 677-716 行（JS）

#### 实现原理
- 使用**预设节点数组**模拟加载进度，共 25 个时间节点
- 每个节点包含：时间（t）、进度（p）、提示文字（h）
- 通过 `requestAnimationFrame` 驱动，在节点间做线性插值

#### 进度节点示例
```javascript
const nodes = [
    { t: 0,     p: 0,   h: '正在初始化...' },
    { t: 380,   p: 10,  h: '正在加载资源...' },
    { t: 1150,  p: 24,  h: '解析场景数据...' },
    // ... 共约25个节点
    { t: 10000, p: 100, h: '完成！' }
];
```

#### 关键特性
- 总时长约 **10 秒**
- 进度 30% 时自动触发 BGM 播放
- 完成时百分比数字有脉冲动画（`pulseComplete`）
- 完成后加载层上浮消失（`float-away` 动画）

### 2. 背景与粒子系统

#### 背景系统
- **随机背景**：从 4 张背景图中随机选择一张
- **Ken Burns 效果**：28 秒缓慢缩放（1 → 1.08），无限交替
- **渐变遮罩**：暗角效果，突出中央内容

#### 粒子系统（微尘）
- 生成 **30 个** 粒子
- 粒子属性随机：位置、持续时间（8-26s）、延迟、漂移距离、大小（1-3.5px）、透明度
- 动画：从底部向上漂浮，带水平漂移，淡入淡出

### 3. 用户名输入与欢迎动画

**文件位置**：第 792-1164 行（JS）

#### 两种欢迎模式

##### ① 普通用户模式（`handleDefault`）
- 用户名淡出 → 欢迎语移动到左上角 → 显示主界面
- 过渡时间约 2 秒
- 用户名为金色高亮

##### ② 特殊用户模式（`specialWelcome`）
**触发条件**：用户名在 `specialColors` 映射表中

```javascript
const specialColors = {
    'SRH': '#c084fc',            // 紫色
    'Shiroha Rin': '#c084fc',    // 紫色
    'Shiroha Nao': '#ffffff',    // 白色
    'IDEA': '#3b82f6',           // 蓝色
    'Hoshina': '#ef4444',        // 红色
    'Shiroha Hoshina': '#ef4444' // 红色
};
```

**动画流程**：
1. 输入框淡出，用户名文字变色发光
2. 文字放大 + 粒子爆发效果
3. 文字模糊消失
4. 逐字显示「欢迎回家，{用户名}」
5. 文字浮动效果（正弦波动画）
6. 模糊淡出，最终移动到左上角固定显示

### 4. 实时天气系统

**文件位置**：第 717-777 行（JS）

#### 实现流程
1. **IP 定位**：调用 `https://ipapi.co/json/` 获取经纬度和城市
2. **天气查询**：调用 `https://api.open-meteo.com/v1/forecast` 获取实时天气
3. **数据渲染**：更新温度、天气图标、天气描述、城市位置

#### 天气代码映射
- 使用 WMO Weather Code 标准
- 支持：晴、多云、雾、雨、雪、雷暴等 20+ 种天气
- 每种天气对应 emoji 图标和中文描述

#### 错误处理
- 网络请求失败时显示 `--°C` 和「获取失败」
- 静默降级，不影响主流程

### 5. BGM 音乐系统

**文件位置**：第 650-665 行（JS）

#### 功能特性
- **自动播放策略**：进度 30% 时尝试播放（受浏览器自动播放策略限制）
- **用户交互解锁**：首次点击页面后，如果 BGM 已启用则自动恢复播放
- **手动开关**：右下角圆形按钮，或按键盘 `M` 键切换
- **循环播放**：`audio.loop = true`
- **音量**：默认 40%（`volume = 0.4`）

#### 状态管理
```javascript
let bgmAudio = null;       // Audio 对象
let bgmEnabled = false;    // 用户是否开启
let bgmActuallyPlaying = false; // 实际是否在播放
```

### 6. 卡片与全屏弹窗系统

**文件位置**：第 1191-1228 行（JS）

#### 卡片列表
| 卡片ID | 标题 | 位置 | 状态 |
|--------|------|------|------|
| `dashboardCard` | 📅 今日概览 | 左上大卡片 | 占位 |
| `artworkCard` | 🎨 艺术作品 | 左下左 | 占位 |
| `aboutCard` | 🧑‍💻 关于本人 | 左下右 | 有内容 |
| `fortuneCard` | 🔮 今日运势 | 右上 | 占位 |
| `musicCard` | 🎵 此刻音乐 | 右中 | 占位 |
| `gameCard` | 🕹️ 小游戏 | 右下左 | 占位 |
| `toolsCard` | 🔧 工具栏 | 右下右 | 占位 |

#### 交互逻辑
- 使用**事件委托**：在 `document` 上监听点击，判断是否点击了 `.glass-card`
- 点击卡片 → 打开全屏覆盖层 → 根据卡片标题渲染对应内容
- **关闭方式**：点击关闭按钮 / 点击遮罩空白区域
- 所有卡片内容目前为占位符，等待后续扩展

## 📱 响应式设计

### 断点设计

| 断点 | 触发条件 | 布局变化 |
|------|----------|----------|
| 桌面端 | > 768px | 左右两栏布局 |
| 平板/手机 | ≤ 768px | 单列纵向布局 |
| 小屏手机 | ≤ 640px | 加载条变宽，BGM按钮缩小 |

### 关键响应式处理
- 使用 `clamp()` 实现流式尺寸（字体、内边距等）
- 使用 `dvh`（动态视口高度）适配移动端浏览器地址栏
- 移动端右栏变为全宽，底部卡片纵向排列

## 🎯 关键技术点解析

### 1. 动画锁机制
```javascript
let specialAnimating = false;
```
- 防止动画过程中重复触发交互
- 所有需要动画的函数入口都会检查此标志

### 2. 文字逐字浮动效果
- 将文字拆分为单个 `<span>`
- 每个 span 设置不同的相位偏移（`idx * 200ms`）
- `setInterval` 每 16ms 更新一次位置，用正弦函数计算偏移量
- 类似「波浪」效果

### 3. 粒子爆发效果
- 沿文字矩形边界按 8px 步长采样
- 每个点以 40% 概率生成粒子
- 粒子向左上方随机飘散，0.6s 后消失
- 用 `setTimeout` 实现从左下到右上的延迟爆发效果

### 4. 浏览器自动播放策略兼容
- 首次尝试播放可能被浏览器阻止
- 监听全局 `click` 事件，用户首次交互后重试播放
- 区分「用户意愿」（`bgmEnabled`）和「实际播放状态」（`bgmActuallyPlaying`）

## 🔧 开发指南

### 如何添加新卡片
1. 在 HTML 的 `.main-layer` 中添加新的 `.glass-card` 元素
2. 在 JS 的点击事件处理中，根据卡片标题添加对应内容的 HTML

### 如何添加特殊用户名
在 `specialColors` 对象中添加键值对：
```javascript
const specialColors = {
    // 已有配置...
    '你的用户名': '#ff6b6b'  // 新添加
};
```

### 如何更换背景图
1. 将图片放入 `resource/images/` 目录
2. 修改 `BACKGROUND_PATHS` 数组，添加新图片路径

### 如何更换 BGM
1. 将音频文件放入 `resource/audio/` 目录
2. 修改 `BGM_URL` 常量为新的音频路径

## ⚠️ 已知问题与注意事项

1. **自动播放限制**：现代浏览器禁止页面自动播放音频，需要用户至少一次点击交互
2. **天气 API 依赖**：天气功能依赖网络和第三方 API，离线环境下无法工作
3. **单文件架构**：所有代码在一个 HTML 中，功能复杂后可能难以维护，建议拆分
4. **无构建流程**：没有使用构建工具，代码压缩、资源优化需要手动处理
5. **卡片功能占位**：大部分卡片只有占位内容，需要后续开发
